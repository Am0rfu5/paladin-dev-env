<assumption_delta_decision>
The deterministic assumption-delta scan fired `pluralization` on this phase's scope. Reading past
the literal trigger word, the genuine transition in scope is this plan's: a single global
`[0.0, 1.0]` temperature clamp — one bound for every provider — becomes a per-provider declared
range with the old global retained for providers that declare none.

- **Primary noun:** the *provider-declared temperature range*. That is now the authoritative
  bound, not a constant in the builder.
- **Decision: `promote`.** The provider-declared range is promoted to primary and checked first;
  the former global `[0.0, 1.0]` is demoted to the named fallback of one variant (a provider
  that has not yet declared a range). This is what ADR-0004 already decided — it is recorded
  here, not re-opened. `add-alongside` is explicitly rejected: keeping the global clamp as a
  second, independent gate would make DeepSeek's 0.0-2.0 range storable but never reachable,
  which is the exact failure ADR-0004 exists to end.
- **Companion invariant test (accepted, wired into Task 2):**
  `test_every_adapter_declares_a_temperature_range` asserts that every shipped LLM adapter
  returns `Some((min, max))` from `get_capabilities().temperature_range`. It goes red the instant
  a future adapter reintroduces the singular assumption by leaving the field `None`.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `PaladinBuilder::validate` | Untrusted caller-supplied `temperature: f32` crosses into configuration that is sent to a paid external provider |
| adapter → `ProviderCapabilities` | An adapter's self-declared capability is consumed by callers who branch on it; an over-reported capability is a false promise across a published contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Tampering | `PaladinBuilder::validate` temperature bound (ASVS V5 Input Validation) | high | mitigate | Validate against the provider's declared range first, inclusive at both endpoints per ADR-0004, and return a typed `PaladinError::ConfigurationError` naming the rejected value. Never clamp: silent substitution alters the caller's request past the point they can discover it |
| T-02-06 | Spoofing | `supports_tool_calling` over-reporting a capability the adapter does not have | high | mitigate | Flip all three adapters to `false` (D-14) and pin the value with a correspondence test that ties the flag to whether a tool-carrying field exists on `LlmRequest` |
| T-02-07 | Denial of Service | A panic in newly-touched validation code taking down the calling process | medium | mitigate | CLAUDE.md's standing rule: no `unwrap()`, `expect()` or `panic!` in library code. The validation path returns `Result`; an acceptance criterion greps the diff for introduced panic sites |

The additive field with a `None` default preserves current behaviour for every unmigrated site |
