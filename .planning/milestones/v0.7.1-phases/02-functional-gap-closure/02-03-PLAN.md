<objective>
Apply the two remaining Phase 1 ADRs that mandate a code change and are independent of the ports
tracer: ADR-0003's Formation minimum-Paladin relaxation and ADR-0001's `citadel.rs` rename.

Purpose: GAP-07 is the requirement that turns Phase 1's recorded decisions into shipped types.
Two contradictions are live in the tree today — `formation.rs` rejects fewer than two Paladins
while the Commander's Auto rule routes a single Paladin to Formation, and `citadel.rs` declares a
`BattalionConfig` that shadows the real Battalion orchestration config of the same name while
being a different concept entirely (checkpoint/resume knobs). ADR-0003 and ADR-0001 settle both;
this plan executes them.

Output: a Formation that accepts one Paladin and still rejects none, and a checkpoint config
whose name says what it is — with the persisted schema untouched.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `Formation::validate` | Untrusted caller-supplied Paladin collection crosses into a domain invariant that gates execution |
| in-memory type → persisted checkpoint file | `BattalionState.config` is serialized to disk by the file-backed Citadel at `schema_version: "1.0.0"` and read back by a later process |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09 | Tampering | `Formation::validate` count bound (ASVS V5 Input Validation) | medium | mitigate | The bound stays an explicit count check returning a typed `BattalionError::ValidationError`; zero remains rejected and is now pinned by `test_formation_rejects_zero_paladins`, so relaxing the bound cannot silently become "no bound" |
| T-02-10 | Tampering | Rename silently altering the persisted checkpoint schema | high | mitigate | Field names, order, types, `#[serde(default)]` attributes and the derive list are held byte-identical; no `#[serde(rename)]` is added and `schema_version` is not bumped. `cargo test --workspace` exercises the file-backed Citadel round-trip |
| T-02-11 | Denial of Service | A panic introduced into domain validation taking down the calling process | medium | mitigate | CLAUDE.md's standing rule: no `unwrap()`, `expect()` or `panic!` in library code. Both edits keep the existing typed-`Result` shape |
| T-02-12 | Repudiation | A stale doc example teaching a type name the crate no longer exports | low | mitigate | The `citadel_port.rs` doc example is updated in the same change even though `doctest = false` means it is not compiled today, so lifting DEBT-03 later does not surface a latent failure |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package-manager install and no new dependency; the workspace dependency graph is unchanged, so existing `make audit` / `make deny` verdicts still hold |
</threat_model>
