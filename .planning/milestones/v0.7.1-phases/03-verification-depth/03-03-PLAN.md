<objective>
Give each of the five MCP tool-invocation failure modes a real, passing, fast test against the
shipped Streamable-HTTP transport.

Purpose: QUAL-04 and ROADMAP criterion 4 name five modes explicitly. Three are reachable by
extending the hermetic rmcp+axum `FixtureServer` this workspace already ships and already proves two
auth-rejection assertions against. Two — malformed response and handshake timeout — cannot be
produced by a spec-compliant rmcp server by construction, so they need a deliberately
non-compliant fixture. The handshake-timeout mode is additionally blocked today by a hardcoded
private 30-second constant with no test seam; this plan adds the minimal additive seam rather than
paying 30 real seconds per run or deferring a mode ROADMAP criterion 4 names by name.

Note the scope: `mcp_protocol.rs` already measures 95.73% line coverage. This work is about the five
*named failure modes having tests*, not about moving a coverage number (D-11).

Output: `MCPClient::connect_streamable_http_with_timeout`, a hardened `FixtureServer::call_tool`, two
new non-compliant fixture servers, and five passing failure-mode tests — all inside the one existing
test file.
</objective>

## Recorded decisions this plan carries

- **Supersedes CONTEXT.md D-11's "driven by `wiremock`" framing.** D-11 named `wiremock` as the
  mechanism. Research Pattern 3 established that the workspace already ships a working hermetic
  rmcp+axum `FixtureServer` in this very file, that `wiremock` has zero existing usages anywhere in
  the repo, and that a `wiremock`-only harness would have to hand-replicate rmcp's `initialize` →
  `notifications/initialized` wire format to reach the post-handshake modes. **The hand-rolled axum
  route is taken first**, keeping the file internally consistent; `wiremock` (already a
  dev-dependency, so no new package either way) remains the documented fallback if hand-matching the
  `initialize` JSON-RPC response shape proves fragile. This supersession is recorded here rather than
  diverging from D-11 silently.
- **All five modes stay in `tests/integration/mcp_streamable_http_test.rs`.** No new file, therefore
  no `pub mod` line and no `Cargo.toml` change, therefore a stable coverage object count for the
  exit measurement (Research Pitfall 3).
- **The timeout seam is rated `costly`, not `one-way`, so it is flagged and not gated.** Undo is
  deleting an added method: nothing migrates, no persisted schema, no breaking signature change. No
  `checkpoint:decision` is emitted for it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP server → MCP client | An untrusted or hostile MCP server's JSON-RPC responses cross into `MCPClient`; malformed, truncated or never-arriving responses are attacker-controllable input |
| client → MCP server | The bearer token crosses outbound on every request; it must not appear in logs, `Debug` output, test output or recorded artifacts |
