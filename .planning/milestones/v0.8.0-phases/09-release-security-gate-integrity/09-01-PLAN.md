## Decomposition note — where this plan set follows D-22 and where it differs

D-22 proposed roughly seven plans in three waves and was authored with full knowledge of the tree.
This set keeps its seven plans and its file-contention rules, and differs in three respects, each
for a reason found after D-22 was written:

1. **Four waves, not three.** `ci.yml` and `Makefile` are touched by three plans (the changelog
   guard, the name guard, and the advisory guard plus the job deletion). D-22 anticipated this and
   offered two remedies — serialise into the SEC-01 plan, or give each a distinct job block. This
   set takes a third: each guard keeps its own plan and its own CI step, and the three are
   serialised across waves 1, 2 and 3 so no two plans ever hold the same file open. That also puts
   the job deletion last, so its line-number shift lands after every other edit to that file rather
   than invalidating them.
2. **A tracer leads the phase.** D-22's wave 1 ① was the register. This set leads with the changelog
   slice instead, because it is the thinnest path that touches every layer the phase modifies — new
   governance file, guard script, `Makefile`, `ci.yml` — and because the repository has already
   shipped a guard that could not fail. Proving the failable idiom end-to-end on the cheapest guard
   before the harder two are written is worth one wave. The register still lands in wave 1, in
   parallel, since it shares no file with the tracer.
3. **`Dockerfile.chef` moved into the SEC-02 blast radius.** `09-RESEARCH.md` §4 placed the OCI
   licence label in the runtime `Dockerfile`; it is actually in `Dockerfile.chef`, which SEC-05 also
   edits. That contention is new information and is why plan 09-05 depends on plan 09-03.

D-00f's medieval-military ubiquitous-language requirement is a standing project convention and
applies to every artifact this phase writes — the Herald changelog below names the crate's own
domain types by their Herald names rather than by generic formatter labels.
