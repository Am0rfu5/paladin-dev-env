<objective>
State the tool-call reachability limitation everywhere the project currently implies otherwise (D-13),
so a developer reading the LLM port or the tool-integration documentation learns the truth Phase 14's
own tree scout found: **no shipped adapter — OpenAI, Anthropic, DeepSeek or the bundled mock — ever
returns a populated `function_call`.** Every producer of one in the workspace is a test double. The
reasoning loop's tool branch in `paladin_execution_service.rs` (Arsenal invocation *and* the
specialist-handoff path) therefore fires only for a consumer supplying their own `LlmPort`
implementation that parses tool calls itself.

This is the documentation half of WEB-04; plan 14-02 fixed the flag (WEB-03) and plan 14-06 writes
ADR-0042, the record this plan's rustdoc and pages point at. D-13's scope guard is binding: the sweep
covers **tool-call reachability claims only**. Milestone 11's fourteen content-currency files are
DOCS-01, Phase 16 — do not widen into them.

Purpose: make every surface describing today's tool-calling behaviour describe today's behaviour, per
the principle D-10 records verbatim from the user.
Output: reachability rustdoc on two `paladin-ports` items plus four corrected documentation pages.
</objective>
