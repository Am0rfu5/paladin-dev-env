<objective>
Build the shared, `Send + Sync` test infrastructure three registers name as a prerequisite and none
has built — the thing that lets a developer writing an async service test reach for an existing
double instead of writing another one-off.

Two DEFER-01 premises are corrected rather than followed, and both are structural rather than
cosmetic. The register places this at `tests/common/`; **that placement cannot work.** Both coverage
targets test from *inside* `src/` via co-located `#[cfg(test)] mod tests` blocks, and `tests/` is a
separate crate that `src/` cannot import from — so `tests/common/` cannot serve the two requirements
DEFER-01 exists to unblock. `src/test_support/`, `#[cfg(test)]`-gated, is the only placement that
works, and it keeps tests able to exercise private paths, which matters for reaching the module bar
(D-08). And the register's `MockNotificationService` **is not constructible as specified**:
`UserService` holds a *concrete* `Arc<NotificationService>`, so no trait double substitutes without
changing a public constructor — but `NotificationService::register_channel_handler` is public, so a
failing channel handler forces the same failure path with no signature change (D-10).

The mock set is **demand-driven** (D-10): build what plans 15-06 through 15-09 actually consume,
verified against real signatures, and write nothing no test calls. Hand-written, following the
`Arc<Mutex<..>>` recording shape already proven three times in this workspace; `mockall` is **not**
adopted (D-09) — it would add a proc-macro dev-dependency, which is a governed act under
ADR-0024/ADR-0036, and a second mocking idiom nobody would retrofit. The per-name verdict for all
five register names is recorded in plan 15-10, after both consumers exist and the verdicts are facts
rather than predictions.

This plan opens the DEFER half. Per **D-11** the two halves are strictly sequential and this plan's
`depends_on` records that boundary: every PIPE plan (waves 1-4) completes before wave 5 begins. The
dependency on plan 15-04 is a sequencing dependency, not a file dependency — the gates that validate
subsequent work exist before the coverage work those gates measure begins.
