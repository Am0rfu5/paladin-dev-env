**Stated limit of the compile-only benchmark gate (`bench-check` / `Benchmark Compile Check`, `cargo bench --workspace --no-run`):** compiling a benchmark target structurally cannot detect a runtime panic. That gate was green throughout the period the dark `benchmark` job's one real dispatch panicked at settings load — a compile check proves the code builds, not that it runs. Recorded here so a future reader does not cite that gate's green result as evidence the benchmarks execute; only `benchmark-regression-signal`'s actual runtime success (and now `benchmarks.yml`'s copy of it) is that evidence.

## Decisions Made

See `key-decisions` in frontmatter.

- **Cron: Monday 06:00 UTC, weekly.** Off-peak, avoids the top-of-hour GitHub Actions scheduler queue. Recorded for `15.1-09`'s trigger-policy table.
- **One scheduled workflow for the phase.** `15.1-05` already retired the nightly integration cron (with its own recorded revisit condition around floating service-image-tag drift); `benchmarks.yml` is the only cadence-driven workflow this phase adds — a second one was not needed and would have duplicated the "weekly is enough" reasoning.
- **`benchmarks.yml` reports no required context by construction.** It carries no required-status-check registration and was verified absent from `protect-main-branch.json`'s pinned list — a cadence job's context could never be satisfied by a pull request and would otherwise block every merge permanently.
- **Comment-text collision with the verify script's literal string count.** The plan's own `<verify>` script asserts `runs.count('APP_ENV=test')==4` (exact, not "at least"). An early draft of the explanatory comment above the seeding step, and an echo line inside the run body, both happened to contain the literal substring `APP_ENV=test` in prose, pushing the count to 6. Reworded both to describe the same behavior ("selecting the test environment") without reusing the literal env-var=value string, restoring the count to exactly 4 (the four real invocations) with no loss of explanatory content. Documented here as a minor authoring correction, not a Rule 1–4 deviation — the fix only touched comment wording, no behavior changed.
