## Decisions Made

- **Context-clause matrix handling unified under one rule.** GitHub Actions produces matrix-leg display names two different ways — a job's `name:` field containing an explicit `${{ matrix.x }}` expression (e.g. `Crate Isolation (${{ matrix.crate }})`), or a job carrying a `strategy.matrix` block with *no* expression in its `name:` at all (e.g. `Unit Tests`, which GitHub auto-suffixes to `Unit Tests (stable)`/`Unit Tests (beta)`). Rather than special-casing the second form, the guard treats both as a literal-prefix match against pinned contexts: for a name containing `${{`, the prefix is the text before it; for a matrix job with no `${{` in its name, the prefix is the full literal name. This single rule correctly resolves all 44 pinned contexts against the current tree, including both matrix shapes.
- **A third positional argument (ruleset-file path) was added beyond the two the pattern doc's usage string names.** `scripts/check-workflow-triggers.sh [workflows-dir] [policy-table-file] [ruleset-file]` — the third argument, defaulting to `.github/rulesets/protect-main-branch.json`, exists so the regression harness can exercise the ruleset-absent skip path and a synthesized context-clause failure without ever touching or renaming the real committed ruleset file. This is a minor, testable extension of the pattern-doc's suggested usage, not a deviation from D-09b's own text (which only specifies the guard's three clauses and register-parsing approach, not its exact CLI surface).
