# Phase 15.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Seeded from `15.1-RESEARCH.md` §Validation Architecture (lines 992–1037).

**This phase is atypical.** Its deliverables are workflow YAML, JSON rulesets, shell scripts,
Markdown/mdbook pages and *live repository configuration*. `cargo test` validates none of them
directly. Three of the seven success criteria (SC2, SC4, SC5) have **no local proxy at all** —
they are assertions about `origin` and about the GitHub API, and their evidence is produced by
observing reality, not by running a command against the working tree. Per CONTEXT.md **D-00e**,
that evidence must be recorded verbatim.

| Property | Value |

---

## Sampling Rate

- **After every task commit:** `cargo deny check advisories` (SC7) and
  `./scripts/check-workflow-triggers.sh` (SC1) — both low-second. Run after any edit to
  `deny.toml`, `SECURITY-EXCEPTIONS.md`, or any file under `.github/workflows/`.
- **After every plan wave:** `mdbook build docs/` (SC3) plus the full local suite above.
- **Before `/gsd-verify-work`:** full local suite green.
- **Phase gate (cannot be sampled locally):** SC2, SC4 and SC5 are live-API / live-CI
  assertions. They are the phase's close-out evidence and must be performed **last**, after
  every other deliverable is merged, in D-02's mandated order.
- **Max feedback latency:** ~30 s for the locally-sampled criteria.
