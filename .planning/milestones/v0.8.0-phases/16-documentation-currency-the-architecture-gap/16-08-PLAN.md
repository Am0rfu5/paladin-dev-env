<objective>
Build the two things DOCS-03's `# Examples` half needs before a single example is written: the D-05
enumeration of what "public API entry point" means, recorded so it can never drift again, and the
gate that checks it.

Purpose: **there is no stable-Rust mechanism to assert "every public entry point has an example."**
`rustdoc::missing_doc_code_examples` exists only behind `#![feature(...)]` on nightly, and every
workflow in this repo pins `dtolnay/rust-toolchain@stable`. A small phase-authored script is the
honest fallback, not a workaround — and saying so plainly in the script's own header stops a future
reader from going to look for a built-in that does not exist.
Output: the enumeration record, `scripts/check-public-api-examples.sh`, and the D-06 heading rule
written into the project's conventions map.

**Measured baseline (D-05):** 47 of 77 resolvable entry-point files already carry an example block;
about 30 do not. The five crates with no example anywhere are `paladin-llm`, `paladin-storage`,
`paladin-web`, `paladin-content` and `paladin-notifications`. `missing_docs` itself is already clean
workspace-wide (M-02) — the open half is the `# Examples` requirement, not the `///` requirement.

**Scope guards:** D-05 — the definition is the 79 items FR-26.3's own wording names (11 builders +
35 `*Port` traits + 33 `*Service` structs). Rejected and not to be revived: all 1,971 items in
`.project/current-exports.txt`, and the 79-plus-204-`pub fn new` reading. D-06 — normalise only the
enumerated entry points; a 364-site sweep was rejected. D-00o — commit with `--no-verify`.
</objective>
