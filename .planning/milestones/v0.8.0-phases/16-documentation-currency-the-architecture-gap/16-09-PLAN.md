<objective>
Give the framework's primary integration contract its examples: every `*Port` trait in
`crates/paladin-ports/` that the D-05 enumeration lists without an example gets one, and the examples
**run**.

Purpose: DOCS-03's own text says the port traits are "the framework's primary integration contract",
and DEBT-03 (Phase 8, commit `2bffe22`) re-enabled `paladin-ports` doctests specifically so their
examples would be *executable* rather than merely present (D-00v). Phase 16 inherits that as input.
This is where the requirement's value actually lands.
Output: `# Examples` blocks on the enumerated port traits, all passing `cargo test --doc`.

**Discretion decision, recorded (Claude's Discretion — doctest disposition).** Default to
**compile-and-run**. Use `no_run` only where the example genuinely needs live I/O or a real adapter
that no mock in the tree provides, and record the reason per example. Never `ignore` or `text` for a
Rust example — those hide compile breakage, which is the exact failure mode a doc example exists to
catch. ADR-0033 Finding 3 records 87 pre-existing `ignore`/`no_run`/`text` fences that DEBT-03
deliberately left un-audited; this plan must not quietly add to that pile.

**Scope guards:** D-05 — the entry-point set is the enumeration, not a fresh interpretation. D-06 —
plural heading spelling on entry points; do not touch non-enumerated sites. D-08 — no workflow edits.
D-00o — `worktree_skip_hooks` is `true`; commit with `--no-verify` and do not run a full-workspace
`cargo test` for self-verification.
</objective>

  <action>
For each enumerated `*Port` trait under `crates/paladin-ports/src/output/` that the record marks as
lacking an example, add an `# Examples` block to that trait's own `///` doc comment (or the file's
`//!` module doc where the file has a single primary export and that is where the crate's existing
examples live).

Each example must show the trait being **used**, not merely named: obtain or construct an implementor,
call the method the trait exists for, and handle the `Result`. Use `?` rather than `unwrap()`/`expect()`
— the repo's Rust conventions require it in examples specifically. Prefer an existing in-tree
implementor or mock as the concrete type; do not author a new adapter just to have something to call.

Disposition each example explicitly:
- **compile-and-run** (a plain ```rust fence) wherever the example can complete without network,
  filesystem writes outside a temp dir, or credentials. This is the default.
- **`no_run`** only where a live adapter or real I/O is unavoidable. Record the reason for each one.
Never `ignore` and never `text` for Rust code.

Heading spelling is `# Examples`, plural, on every entry point (D-06).

Do not change any trait signature, add a method, or widen a visibility. This is a documentation task:
the only lines that change are doc-comment lines. If an example cannot be written without an API
change, stop and record that as a finding rather than making the change here.

After the batch, run `cargo test --doc -p paladin-ports` and fix any example that fails to compile or
run. Then run the workspace doc gate to confirm no new intra-doc-link warning was introduced by the
new prose, and run `bash scripts/check-public-api-examples.sh --list` to record the reduced violation
count.
  </action>
