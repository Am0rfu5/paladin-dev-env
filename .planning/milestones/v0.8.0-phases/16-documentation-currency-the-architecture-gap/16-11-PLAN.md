anywhere else in the phase.

  <action>
For each enumerated entry point in the five crates that lacks an example, add an `# Examples` block to
that item's own `///` doc comment, or the file's `//!` module doc where the crate's existing
convention puts it there.

**Offline first.** Reach for the in-tree offline implementor before anything else:
`MockLlmAdapter` for the LLM surface, the sqlite or in-memory repository for storage, an in-process
router construction for the web surface. `examples/basic_paladin.rs` is the proof that this pattern
runs offline at exit 0 with no credentials — copy that shape.

**Never put a credential in an example, real or realistic.** Where an example must show configuration
carrying an API key, read it from an environment variable in the example body rather than writing a
literal that looks like a key. A doc example is published to docs.rs verbatim; a plausible-looking
literal invites a copy-paste that ships. This is the same manual credential-handling review the repo's
`security.instructions.md` requires of any code touching an API key.

**`no_run` is legitimate here — but reasoned.** A provider adapter that would POST to a vendor, a
MySQL repository that would need a live server, a web handler that would bind a port: these get a
`no_run` fence with a one-line reason recorded per example. What is not acceptable is `no_run` chosen
because the example was awkward to make compile. Never `ignore` and never `text`.

Plural `# Examples` heading (D-06). No signature or visibility change — only doc-comment lines may
appear in the diff. Where a type sits behind a Cargo feature, place its example inside the same
`#[cfg(feature = …)]` region so the default-feature doc build still compiles.

Run the crate-scoped `cargo test --doc` for each of the five, fix any failure, then re-run the
workspace doc gate.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| doc-comment source → published rustdoc + docs.rs | Adapter and service examples are the code a user copies to talk to a provider or a database; a credential-shaped literal here ships to every reader. |
| doc examples → `cargo test --doc` | Doctests execute; a provider example that ran would POST to a vendor endpoint. |
| feature-gated adapters → default-feature doc build | Most adapters in these five crates sit behind Cargo features. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-29 | Information Disclosure | a credential-shaped literal in a published example | high | mitigate | Examples read any key from an environment variable rather than writing a literal; an acceptance criterion greps the diff for bearer-prefixed and `api_key = "…"` shapes. This is the manual credential-handling review `.github/instructions/security.instructions.md` requires of any code touching an API key, applied to documentation. |
| T-16-26 | Information Disclosure | a doctest reaching a vendor endpoint or a live database | high | mitigate | Offline in-tree implementors first (`MockLlmAdapter`, sqlite/in-memory repositories); anything that would perform real I/O is `no_run` with a recorded reason, so `cargo test --doc` never leaves the process. |
| T-16-17 | Tampering | gate-appeasement instead of a real example | high | mitigate | Prohibition on `no_run`/`ignore`/`text` chosen to dodge compilation; every `no_run` carries a recorded reason; the diff is grepped for added `ignore`/`text` fences and singular headings. |
| T-16-18 | Tampering | widening an API to make an example compile | high | mitigate | Only doc-comment lines may appear in the diff; an acceptance criterion asserts no `pub` declaration line changed. `.project/current-exports.txt` plus `scripts/check-api-surface.sh` make an unintended widening detectable. |
| T-16-28 | Tampering | an example on a feature-gated adapter breaking the default build | medium | mitigate | Each gated example is placed inside the same `#[cfg(feature = …)]` region as its type; the default-feature `cargo doc --workspace --no-deps` is the acceptance gate. |
| T-16-30 | Tampering | rustdoc examples and the compile-verified examples crate drifting apart | medium | mitigate | The two systems stay separate by design (RESEARCH.md "Don't Hand-Roll"), but any contradiction on import path or construction order is fixed on the rustdoc side; `scripts/check-doc-examples.sh` is run as an acceptance gate so the examples crate is proven unbroken. |
| T-16-SC | Tampering | package-manager installs | low | mitigate | This plan installs nothing and adds no dependency; examples use only in-tree types. `make audit` / `make deny` posture is unchanged. |
</threat_model>
