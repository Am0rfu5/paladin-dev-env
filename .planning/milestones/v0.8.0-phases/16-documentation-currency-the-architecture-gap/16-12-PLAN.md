<objective>
Close DOCS-03. Normalise the heading spelling on the enumerated entry points and only there, then
prove both gates green with their output recorded verbatim.

Purpose: the tree carries two heading spellings — the singular form at roughly 212 sites and the
plural at roughly 152 — and rustdoc renders both identically, so this is house style, not
correctness. D-06 therefore normalises **only** the 79 enumerated entry points, so FR-26.3's wording
is literally grep-satisfiable where the requirement points, and explicitly rejects a 364-site sweep
that would touch hundreds of files for zero rendered-output change.
Output: a consistent heading on the enumeration, both gates green, and the closing evidence recorded.

**Scope guards:** D-06 — the enumerated entry points only; the other sites are left alone by design.
D-08 — the gate mechanism is untouched; do not switch to rustdoc's deny mode (that is a Deferred Idea
needing its own ADR, because the current grep-on-`tee` check can match a per-crate summary line as
well as a real warning) and do not add an mdbook or linkcheck gate. D-00u — the CI gate already
exists at `ci.yml:63`; this phase applies the bar, it does not create the gate. D-00o — commit with
`--no-verify`.
</objective>

Change the heading on every enumerated entry point whose block still uses the singular spelling to the
plural form. Work strictly from the enumeration record's rows — not from a tree-wide search-and-replace.

**The boundary is the whole point.** A tree-wide sweep of the roughly 364 heading occurrences was
offered and rejected under D-06: rustdoc renders both spellings identically, neither is a warning, so
a 364-site edit would touch hundreds of files for zero change in rendered output and would bury this
phase's real content fixes in review noise. Touch a heading only if the item it documents appears in
the enumeration. Everything else keeps whatever spelling it has.

Do the edit line by line against the enumerated `file:line` values, and after each file re-read the
block you changed to confirm you changed a heading and not a prose line that happens to contain the
same words.

When the enumerated set is normalised, run `bash scripts/check-public-api-examples.sh` in its default
gating mode. It must exit 0. If it still reports a row, fix the underlying documentation — do **not**
adjust the script's scope, relax its matching, or remove a row from the enumeration to make it pass.
A gate edited to fit the tree measures nothing.

Then record the count of untouched non-enumerated sites as evidence that the boundary held: run the
tree-wide singular-heading count before and after this task and show that the difference equals
exactly the number of enumerated rows you changed.
