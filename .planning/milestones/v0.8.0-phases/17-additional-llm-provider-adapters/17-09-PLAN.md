carries the live `x-goog-api-key` credential.

17-11 expand into the same file.

**Purpose:** verification scored 6/9 with exactly one failed truth — *"New adapter code is free of
unresolved Critical-severity security defects."* Every other adapter this phase added carries
`model` inside the JSON request body (`compat/types.rs::CompatRequest.model`, serde-encoded, safe).
Gemini is the sole URL-path case (D-08 makes it the one bespoke-protocol adapter), so this is an
isolated fix, not a design problem.

**Output:** a private `validate_model_identifier` guard in `gemini/adapter.rs`, wired as the first
statement of `generate()` and `generate_stream()`, plus twelve regression tests. No new
dependency, no new public symbol, no change to `LlmPort`.

Add the guard and wire it. Production code only in this task, plus its own unit tests.

**1. The guard.** Add a private module-level free function alongside `candidate_text` /
`map_finish_reason`:

  `fn validate_model_identifier(model: &str) -> Result<(), LlmError>`

Its rules, in order:
  - empty input → `Err(LlmError::InvalidPrompt(..))`
  - any character `c` where `!(c.is_ascii_alphanumeric() || matches!(c, '.' | '_' | '-'))` →
    `Err(LlmError::InvalidPrompt(..))`
  - no character satisfies `is_ascii_alphanumeric()` → `Err(LlmError::InvalidPrompt(..))`
  - otherwise `Ok(())`

Use `chars()`, never byte indexing or slicing — a byte-index into a multi-byte value is how this
kind of guard acquires the panic that CLAUDE.md forbids in library code. No `unwrap()`, no
`expect()`, no `panic!`.

The error message must: name the offending field (`model`), state the permitted set in words
(ASCII letters, digits, dot, underscore, hyphen), name `GEMINI_MODEL` as the environment variable an
operator would correct, and embed the offending value **only** via
`bounded_excerpt(model, RESPONSE_EXCERPT_CHAR_BUDGET)` — never the raw `model` string, which is
caller-supplied and unbounded.

**2. The rustdoc.** Give the guard a `///` block recording three things, because each is a decision
a future maintainer would otherwise re-litigate:
  - It closes CR-01: `request.model` is interpolated into the request *path*, unlike every
    `CompatEngine`-based preset which carries the model inside the serde-encoded JSON body.
  - Why an allow-list rather than encoding the segment: every character in
    `[A-Za-z0-9._-]` is URL-unreserved, so encoding an already-valid value is a no-op and encoding
    an invalid one silently rewrites the caller's request into a different one. Rejecting is louder
    and adds no dependency — `percent-encoding` is not a declared dependency of this crate today,
    and PROV-01's own criteria treat a new dependency as a cost that `make deny` / `make audit`
    must still clear.
  - Why not a membership check against `self.available_models()`: that would put a network fetch in
    the hot path of every `generate()` and would reject any model the provider shipped after this
    release — the exact behaviour D-13 exists to prevent.

**3. Wire it.** Call `validate_model_identifier(&request.model)?` as the **first statement** of both
`generate()` and `generate_stream()` — ahead of `self.build_request(&request)?` and ahead of the
`format!` that builds the URL. Both sites must be guarded; guarding only the non-streaming path
leaves the injected-query vector open on exactly the path where the SSE-framing parameter matters.

Leave `fetch_live_models`'s URL alone — it interpolates only `self.config.base_url`, which
`GeminiConfig::validate()` already checks and which is operator-supplied, not caller-supplied.

**4. Module doc.** Add a `## Trust boundary: the caller-supplied model identifier` section to the
`gemini/adapter.rs` module doc comment, in the shape `openai_compatible/adapter.rs` uses for its own
trust-boundary section: the field crosses from caller to URL path, the guard is what stops it, and
the residual accepted case is the operator's own `GEMINI_BASE_URL` (a separate trust decision, and
the subject of plan 17-10).

**5. Unit tests.** Add five pure-logic tests to the test module — these exercise the guard directly,
where Task 1's tests exercise it through the public surface:
  - `validate_model_identifier_accepts_the_default_and_every_fallback_model`
    — iterate `std::iter::once(GEMINI_DEFAULT_MODEL).chain(GEMINI_FALLBACK_MODELS.iter().copied())`
    and assert `Ok` for each. This is the regression guard that the fix can never break a shipped
    default.
  - `validate_model_identifier_rejects_each_url_metacharacter`
    — table-drive over at least `'/'`, `'?'`, `'#'`, `':'`, `'@'`, `'%'`, `'&'`, `'='`, `' '`,
    `'\\'` and `'\n'`, each spliced into an otherwise-valid identifier; assert
    `Err(LlmError::InvalidPrompt(_))` for every one, with the offending character in the assertion
    message.
  - `validate_model_identifier_rejects_a_value_with_no_alphanumeric_character`
    — `"."`, `".."`, `"---"`, `"_"`.
  - `validate_model_identifier_rejects_a_long_multibyte_value_without_panicking`
    — build a 2,000-character string by repeating a multi-byte character, assert `Err`, and assert
    the message's `chars().count()` is bounded by `RESPONSE_EXCERPT_CHAR_BUDGET` plus a small
    fixed prefix allowance. The test completing at all is what proves no mid-codepoint slice
    occurred.
  - `validate_model_identifier_accepts_every_character_of_the_allowed_set`
    — one identifier exercising each allowed class together, e.g. `"aZ0.9_x-1"`.
