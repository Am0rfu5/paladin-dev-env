<objective>
Close the **new WR-03** — Gemini's `parse_response`
(`crates/paladin-llm/src/gemini/adapter.rs:400-429`) has no equivalent of
`CompatEngine::detect_empty_completion` (`crates/paladin-llm/src/compat/engine.rs:277-287`).

**Note the finding-ID collision.** This is *not* the auth-classification WR-03 that plan 17-11
closed and `17-VERIFICATION.md` Truth 5 records as verified. `17-REVIEW.md`, dated after that
gap-closure run, reused the label for a different defect. This plan closes the *new* one; nothing
plan 17-11 built is touched.

`CompatEngine::detect_empty_completion` maps `finish_reason == Length` combined with blank content
to `Err(LlmError::EmptyCompletion(..))`, on the documented rationale that this is the
reasoning-model signature — the model consumed its whole `max_tokens` budget before producing
visible text. Every Kimi, Qwen, Grok, Ollama and generic-provider call passes through that check.
Gemini's `parse_response` does not: a response with `finishReason: "MAX_TOKENS"` and an empty
`parts[]` array returns `Ok(LlmResponse { content: "", finish_reason: Length, .. })`.

**Purpose:** a caller written against this crate's error-signal contract — checking for
`LlmError::EmptyCompletion` rather than inspecting `finish_reason` on every success path — gets a
silent truncated "success" from exactly one of the six adapters this phase shipped. That is the same
inconsistency class PROV-02 exists to prevent: *"errors map into the existing `LlmError` variants"*
and each built adapter *"passes the same contract tests the existing three do."* `parse_response`'s
own doc comment already claims it *"fails with `EmptyCompletion` … rather than ever returning `Ok`
with empty content"* — a claim the code does not currently keep.

**Output:** a two-condition guard in `parse_response`, a corrected doc comment, and five regression
tests including two adjacency controls and one refusal control that keeps the guard from becoming a
catch-all.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `generativelanguage.googleapis.com` → `parse_response` | The provider's response envelope is untrusted structured input. Whether it is classified as a success or an error is decided here and cannot be recovered by the caller afterwards. |
| `parse_response` → caller | An `Ok` with empty content and an `Err(EmptyCompletion)` are different contracts. A caller that checks the error type and not `finish_reason` acts on whichever this function chooses. |
| `parse_response` → `execute_with_retry` | The chosen `LlmError` variant is the retry decision. `EmptyCompletion` is in the non-retryable set. |
