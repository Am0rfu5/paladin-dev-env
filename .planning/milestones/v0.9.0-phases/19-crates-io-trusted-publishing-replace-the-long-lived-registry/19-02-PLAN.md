<objective>
Replace the standing repository secret with a credential the job mints for itself, and put the job
behind a gate that decides which refs are even allowed to ask for one.

Two halves that only work together. The OIDC exchange is what makes the credential short-lived;
the GitHub Environment is what makes it narrow — its name is embedded in the OIDC subject claim
crates.io validates, so an environment pinned to `v*.*.*` tags is the difference between "this
repository may publish" and "a release tag from this repository may publish". The same edit
removes the branch that let a release finish green having published nothing.

Purpose: PUB-02 and the failure-honesty half of PUB-05 land here. Nothing in this plan claims the
OIDC path works — that claim belongs to 19-03's proof event, and this plan deliberately does not
make it.
Output: a rewritten `publish-crates` job and a `crates-io` repository environment restricted to
release tags.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runtime → crates.io OIDC endpoint | A workflow-identity JWT crosses to an external relying party which decides, on the claims alone, whether to issue a publish-scoped token |
| repository refs → the `publish-crates` job | Whichever refs can reach this job can ask GitHub to mint an identity token naming this repository |
| workflow YAML → repository settings | The environment name in the YAML and the environment object in settings are two records of one fact; a mismatch silently auto-creates an unprotected environment |
| minted token → workflow logs and step outputs | A short-lived credential passes through the runner's step-output plumbing |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-07 | Elevation of Privilege | Untrusted ref reaching a job with `id-token: write` | high | mitigate | Task 1 restricts the `crates-io` environment to `v*.*.*` tags typed as a tag rule; the existing `verify-tag-source` job independently rejects a tag whose commit is not an ancestor of `main`. Both must pass before any mint is attempted. |
| T-19-08 | Elevation of Privilege | Environment auto-created unprotected because the YAML names one that does not exist | high | mitigate | Task 2 carries a precondition asserting the environment already exists, and Task 1 runs first in the same plan; the acceptance criteria read the live policy back rather than assuming the write succeeded. |
| T-19-09 | Repudiation | A release ending green having published nothing | high | mitigate | The token-presence check and the third mode value are deleted rather than rewritten (D-09); acceptance criteria assert zero occurrences of the deleted branch, zero repository-secret reads, and zero error-suppressing step flags anywhere in the file. |
| T-19-10 | Spoofing | Confused-deputy trigger minting a token on attacker-influenced context | high | mitigate | crates.io blocks `pull_request_target` and `workflow_run` from Trusted Publishing outright; `release.yml` declares only a `v*.*.*` tag push and `workflow_dispatch`, neither in that blocked set, and this plan changes no trigger — `scripts/check-workflow-triggers.sh` is run as an acceptance criterion to prove it. |
| T-19-11 | Information Disclosure | Minted token appearing in a workflow log | medium | mitigate | The token is consumed only as a step-level `env:` value sourced from `steps.auth.outputs.token`, which GitHub masks in logs; no step echoes it, and no shell construct interpolates it into a message.
