<objective>
Destroy the standing credential on both sides, in the order that makes the destruction real.

The phase is not finished when the OIDC path works; it is finished when the old secret no longer
exists. A repository holding both a working OIDC path and a live publish-scoped token has added a
publish path rather than replaced one — which is a net increase in attack surface, not a
reduction. And of the two halves, revocation at crates.io is the load-bearing one: deleting the
repository secret alone removes one copy of a credential that is still valid wherever else it was
ever pasted — another CI system, a laptop's `~/.cargo/credentials`, a password manager entry.

Purpose: PUB-04, the criterion that makes this a migration instead of an addition.
Output: a revoked crates.io token, a deleted repository secret, and a credential-history record
that names what was observed for each.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crates.io account → the publish-scoped token's other copies | Revocation at the registry is the only action that reaches every copy of the credential, wherever it was pasted |
| repository secret store → workflow runs | While the secret exists, any workflow change that can read it can publish |
| what was done → what was recorded | A credential event that is not recorded with an observation is indistinguishable from one that did not happen |
