<objective>
Write the configuration down where the next person will look, and record what was destroyed with
the same discipline the project already requires of an advisory suppression.

With eleven crates the trust configuration is a configuration, not a step. It lives entirely in
crates.io's per-crate settings — no in-repo artifact enforces it — so if it is not documented it
must be reconstructed by opening eleven settings pages, in a workspace where crate names do not
match directory names. That reconstruction cost is exactly what criterion 6 exists to prevent.

Purpose: the documentation half of PUB-05, the record half of PUB-04, and the operator-facing half
of PUB-01's reconciliation. Also the honesty criterion: nothing here may claim a protection this
phase did not establish.
Output: a rewritten release-automation appendix carrying the trust table and the credential
history, a reconciled release checklist, a corrected contributor setup section, and a changelog
entry.
</objective>
