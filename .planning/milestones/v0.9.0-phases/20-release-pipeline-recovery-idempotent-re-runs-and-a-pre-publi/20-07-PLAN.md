<objective>
Exercise the recovery path against a real induced partial failure on a throwaway prerelease version,
and record what happened — or, if the operator declines, leave the runbook honestly labelled
untested. This is the phase's actual integration test: no unit test can create a half-published
state on a public registry, and D-14 explicitly rules out a dry run as evidence.

Purpose: PUBOPS-05's second half and the roadmap's seventh success criterion. Everything before this
plan is a procedure that has been written down; this plan is the only thing that can make it a
procedure that has been proven.

Output: `20-RECOVERY-EVIDENCE.md` in the phase directory, in the `19-PUBLISH-EVIDENCE.md` style, and
a runbook status line that matches reality.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator action → public registry | The rehearsal publishes irreversibly to crates.io |
| GitHub Actions re-run → `crates-io` environment deployment policy | The re-run must still satisfy the tag-ref policy that mints the publish token |
| recorded evidence → future operator's trust | A claim in the evidence file becomes the basis for acting during a real incident |

| T-20-25 | Elevation of Privilege | `crates-io` environment policy under a re-run | high | mitigate | The rehearsal is the concrete test of Assumption A3; the recovery step explicitly observes whether the environment gate and OIDC exchange succeed on the re-run, and the result is recorded either way rather than assumed |
