<objective>
Make the GitHub release body the curated `CHANGELOG.md` section for the tag's version, and make a
missing section a hard, named failure.

Purpose: `create-release` currently builds its body from `git log --pretty=format:"- %s"` over the
whole range since the previous tag — for v0.8.0 that is 1,014 commit subjects — while the project
maintains a hand-authored Keep-a-Changelog corpus on purpose. The pipeline discards the artifact
the project chose to curate, and prints a `docker pull …:latest` instruction that has never worked
on a release. This plan closes ARTIFACT-01 and the body half of ARTIFACT-03.

Output: `scripts/extract-changelog-section.sh`, its regression harness, and a `create-release` job
whose body is the curated section and nothing else.
</objective>

Create `scripts/extract-changelog-section.sh` following `create-or-reuse-release.sh`'s header
shape: a purpose comment naming ARTIFACT-01, an explicit `Usage`/`Output`/`Exit` contract block,
`set -euo pipefail`, and a sourcing seam `EXTRACT_CHANGELOG_SECTION_LIB_ONLY=1` that loads
`extract_changelog_section_main` without executing it.

Contract: `--changelog <path>` (default `CHANGELOG.md`), `--version <X.Y.Z|vX.Y.Z>` (required),
`--output <path>` (optional; when given, write the section there and print `section_file=<path>`
to stdout and append the same line to `$GITHUB_OUTPUT` when that variable is set and non-empty;
when omitted, print the section to stdout). An unrecognised flag is a usage error.

Normalise the version by stripping at most one leading `v`, matching
`check-release-consistency.sh`'s `${TAG#v}` exactly. Implement the boundary scan in a
`python3 - <<'PY'` heredoc, as every other text-processing guard in `scripts/` does, so
`re.escape` handles the dot and hyphen in a prerelease version rather than a hand-rolled
sed/awk escape. Start boundary: the first line matching `^##\s*\[<escaped version>\](\s|$)` —
carry a comment cross-referencing the sibling clause in `check-release-consistency.sh` by name and
line so the two implementations can never silently diverge (this repo's documented-parallel
convention, per the RESEARCH "Don't Hand-Roll" row). Stop boundary: the next line matching
`^##\s*\[` or end of file. Emit everything strictly between the two boundaries — the heading line
itself is not part of the output — with no trimming, re-wrapping, case folding, or line-ending
rewriting of the author's text.

When no start boundary is found, write to stderr the exact message
`::error::no ## [X.Y.Z] section in CHANGELOG.md -- run make release VERSION=X.Y.Z (finalizes changelogs) before tagging`
with `X.Y.Z` replaced by the normalised version, and exit 1. There is no alternate body source
in this script, and none is added to the calling job (D-01).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tag ref / `workflow_dispatch` input → workflow `run:` body | The version string ultimately traces to an operator-supplied input |
| repository `CHANGELOG.md` → GitHub Releases API payload | Author-written multi-line text crossing into an HTTP body |
| runner → api.github.com | Credential-bearing (`GITHUB_TOKEN`) request from a `contents: write` job |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-01 | Tampering | `create-release` `Extract changelog section` step | high | mitigate | The version reaches the `run:` body only through `env: RELEASE_VERSION` (CR-01), never `${{ }}`-interpolated into the shell; the script quotes it in every expansion |
| T-21-02 | Tampering | `extract-changelog-section.sh` output → release body | high | mitigate | The section is written to a `$RUNNER_TEMP` file and passed as `--body-file`; it is never echoed into `$GITHUB_OUTPUT` via a heredoc (a changelog line equal to the delimiter would terminate it early) nor concatenated into a command line — `create-or-reuse-release.sh`'s `jq -n --arg` builds the payload structurally |
| T-21-03 | Information Disclosure | `gh api` calls in `create-or-reuse-release.sh` | medium | accept | Unchanged by this plan; the existing no-redirect-follow control (`-L` is never passed) already governs it and is re-asserted, not re-implemented |
| T-21-04 | Denial of Service | release body size | low | accept | A curated section is bounded by what a human writes; the unbounded-growth class belongs to the finalize job and is mitigated in plan 21-03 |
| T-21-SC | Tampering | package installs | low | accept | RESEARCH.md's Package Legitimacy Audit records **no new packages, no new Actions** in this phase; `python3`, `gh` and `jq` are runner-preinstalled first-party/system tools. No install step, so no legitimacy checkpoint applies |
