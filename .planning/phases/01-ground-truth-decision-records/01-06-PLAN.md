<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| task-list checkbox state → ledger verdict | checkbox state is the least reliable signal in this corpus and has been wrong in both directions across three ingest runs |
| ADR verdict → ledger row | an ADR outranks the tree, so a ledger row that copies the ADR's answer as the tree's current state would hide the work GAP-07 must do |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-16 | Spoofing | a `satisfied` verdict asserted without a re-checked citation | high | mitigate | The D-19 evidence bar is written into the task action as a two-part requirement (citation AND named exerciser), the first prohibition forbids memory-based verdicts, and the acceptance criteria require every cited `file:line` to resolve. |
| T-01-17 | Tampering | a `must change` ADR read as already-conformant in a ledger row | high | mitigate | Task 2's action states explicitly that an ADR outranking the tree does not make the tree conform; the row records today's code and names the ADR plus GAP-07 as what changes it. Asserted as an acceptance criterion. |
| T-01-15 | Tampering | outstanding work downgraded to deferred | medium | mitigate | The second prohibition requires a citation to an actual deferral; inference from work-not-done is forbidden. |
| T-01-18 | Repudiation | a paraphrased task item that cannot be joined back to its source | medium | mitigate | The third prohibition requires literal checkbox text, and each nested item cites its task file and line so the join is mechanical. |
