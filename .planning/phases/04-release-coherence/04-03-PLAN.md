## Decisions this plan records (open questions RESEARCH left to the planner)

1. **Only `ci.yml` gets the `release/**` trigger.** `integration-tests.yml:3-16` and
   `feature-flags.yml:3-9` carry the identical commented-out stanza, but D-14 names `ci.yml` alone
   and `integration-tests.yml`'s modernization belongs to PIPE-04 (Phase 15). Leaving them
   untouched is deliberate; the SUMMARY records it so a reader does not read it as an oversight.
   **Owner of the sibling-workflow question: Phase 15 / PIPE-04.**
2. **The 5-minute Docker budget applies to the whole multi-arch buildx invocation, not per
   architecture.** SC5 says "the multi-arch Docker build inside its size and time budget" — one
   build, one budget. This is the strict reading and it is very likely to fail on first real
   execution: the only measured Docker build time anywhere in the corpus is `PROJECT.md:767`'s
   **112 MB built in 5m31s**, and that was a *single-arch* build already over five minutes;
   QEMU-emulated `linux/arm64` on an amd64 runner is markedly slower. The gate is authored to fail
   anyway, because a red gate on first execution is the measurement REL-05 has never taken.
   Softening it to a warning would report a budget as met that has never been met.
   **Owner of the disposition — revise the figure with evidence, or optimise the build: Phase 15 /
   PIPE.**
3. **The Kubernetes smoke job reuses the existing placeholder-based shape.**
   `k8s/deployment.yaml:66-68` runs `command: ["/bin/sh"]` with a `sleep 3600` placeholder and all
   three probes commented out at `:137-174`, so the startup budget measures container scheduling,
   not application readiness. The job is still worth having — it genuinely proves kind/kubectl
   orchestration and the manifest set apply cleanly, which is what D-14.3 literally asks for.
   Wiring real readiness probes needs `paladin-web` health endpoints in the Deployment, which is
   new product capability and outside this phase's boundary.
   **Owner of the probe wiring: Phase 14 / WEB.** (Not assigned in `04-CONTEXT.md`'s deferred list;
   nominated here, per RESEARCH Part B Open Gap 2.)
4. **Budget boundary values pass.** All four figures are upper bounds where equality is inside the
   budget — 500 MB, 300 s, 30 s and 15 min each use a strictly-greater-than comparison, matching
   the `-gt` form already used at `release.yml:563` and `integration-tests.yml:245`.
5. **Job naming.** The examples job's display name uses `Muster`, which already has in-repo
   precedent (`examples/muster_baseline.rs`) and correctly means assembling the full set. No
   glossary term maps to a Kubernetes cluster deployment, so the Kubernetes job keeps plain
   language rather than minting a new term — inventing vocabulary would dilute the ubiquitous
   language rather than honour it.
