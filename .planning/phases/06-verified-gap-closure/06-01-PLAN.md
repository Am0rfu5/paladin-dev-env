<objective>
Close CLOSE-01: make Grove LLM routing use the model the operator configured, and fail loudly when
no model is configured.

Purpose: `crates/paladin-battalion/src/grove_service.rs:537` builds its routing `LlmRequest` with a
hardcoded OpenAI model literal in production code, so a Grove configured for Anthropic or DeepSeek
silently routes through OpenAI. This is the only defect Phase 5 verified open in Milestone 2-3
scope, and it is what ROADMAP success criteria 1 and 2 measure.

Output: a `routing_model: Option<String>` knob on `GroveConfig` threaded through `GroveBuilder`
(D-01), a hard `BattalionError::RoutingError` when it is absent under LLM routing with no fallback
of any kind (D-02), and a recording-mock test proving a non-OpenAI model reaches `generate()`
(D-04).

**Task ordering note.** D-02 is rated **one-way** in `06-CONTEXT.md` — it is a deliberate runtime
behaviour break for any Grove already using `RoutingStrategy::LlmRouting`. `REVERSIBILITY_GATES` is
on, so a `checkpoint:decision` gates the door before the agent walks through it. Task 1 is that
gate; Task 2 is the phase's leading tracer and the first task that writes code.

**Executor note:** `.planning/config.json` sets `workflow.worktree_skip_hooks: true`. Do not
disable it — without it every commit cold-compiles the whole workspace inside the worktree.

**Spec-less probe fallback.** This phase has no SPEC.md. This plan carries edge-probe rows
CLOSE-01/adjacency, CLOSE-01/empty, CLOSE-01/ordering and CLOSE-01/concurrency, authored as
`must_haves.truths` prefixed `[edge/...]` (4 of the phase's 8; the other 4 live in 06-03, 06-05 and
06-07). One prohibition survived Stage-2 precision for CLOSE-01 and is authored descriptor-less
above. **Canon-referral breadcrumb (recorded, not minted):** "API-key / provider-credential
leakage through logs is canon — covered by `/gsd-secure-phase`, `make audit` and the existing
`BearerToken` redaction convention; not minted here."

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator configuration -> Grove routing | `GroveConfig` arrives from a YAML/JSON document or a builder call written by the operator; its `routing_model` decides which external vendor receives routing prompts |
| Grove routing -> external LLM provider | `route_by_llm` sends the task text plus every Tree and agent name to whichever provider backs the configured `LlmPort` |
