<objective>
Close 06-VERIFICATION truth 3: make D-02's "no fallback of any kind" guarantee reachable from
`GroveExecutionService::execute()`, the only public entry point, and prove it with a test that drives
`execute()` rather than the crate-private `route_by_llm`.

Purpose: `route_by_llm` returns the correct `BattalionError::RoutingError` when `routing_model` is
absent under `RoutingStrategy::LlmRouting`, but `route_task` — the only caller `execute()` goes
through — wraps every strategy call in a blanket `match result { Err(e) => ... }` that catches *any*
error, including this deliberate no-fallback-by-design one, and substitutes `fallback_tree` or the
first agent in the first tree instead. `GroveBuilder::build()` guarantees at least one non-empty
tree, so that terminal fallback can never itself fail. Net effect: a misconfigured Grove does not
error through `execute()` — it silently bypasses LLM routing entirely. `route_task` was not touched
by plans 06-01 through 06-07; the defect is a pre-existing catch-all that orphans the new guard.

Output: one shared resolver used by both `route_task` and `route_by_llm`, a pre-dispatch early return
in `route_task` for the missing-configuration case only, and `execute()`-level tests — including one
with a configured `llm_port` — that assert the error.

**Scope.** Exactly `06-VERIFICATION.md`'s `missing:` items (a) and (b). Nothing else. Truths 1, 2, 4,
5, 6, 7, 8 and 9 of that report are verified and are not re-planned here. Item (c) — reconciling the
permanent project records — is plan 06-09 and 06-10, which depend on this plan landing first.

**No checkpoint, deliberately.** D-02 is rated `one-way` and this plan carries that rating on Task 1
for the record. It gets no `checkpoint:decision`: the human already walked through this exact door on
2026-08-05 at plan 06-01 Task 1 and selected `proceed-as-locked`
(`06-01-SUMMARY.md`, quoted in ADR-0013's `## Checkpoint outcome`). Re-asking would be the
"gating a decision already made" anti-pattern. This plan makes the approved decision real; it does not
re-open it, and it does not soften it.

**Chosen shape, and why not a new error variant.** `06-REVIEW.md` CR-01 suggested a new
`BattalionError::RoutingConfigurationError` variant. This plan does not take that route.
`BattalionError` (`crates/paladin-core/src/platform/container/battalion/mod.rs:762`) is a public enum
with no `#[non_exhaustive]` attribute, so adding a variant is a semver-breaking change for every
downstream exhaustive `match`, and it would falsify ADR-0013 and `CHANGELOG.md`, which both name
`BattalionError::RoutingError` as the error operators will see. Resolving the model *before* dispatch
in `route_task` keeps the error type exactly as already documented, adds no public surface, and is
`reversible` rather than `costly`.

**Spec-less probe fallback.** This phase has no SPEC.md. The deterministic edge probe returned one
row for CLOSE-01 classified `unclassified` / `unresolved` with the note "review manually". Resolution
recorded here, not silently dropped: the planner resolved it to **covered**, because a defensible
acceptance criterion can be written for it — the missing/blank-`routing_model` case observed through
`execute()`, which is `06-VERIFICATION.md`'s own `missing:` item (b). It is authored as the plain
`[edge/CLOSE-01/unclassified]` truth above. The remaining four probe rows (CLOSE-02 × 3, CLOSE-03 × 1)
are authored in plan 06-10. Probe-item accounting for this plan: 1 surfaced, 1 authored, 0 dropped.
One prohibition survived Stage-2 precision for CLOSE-01 and is authored descriptor-less above.
**Canon-referral breadcrumb (recorded, not minted):** "API-key / provider-credential leakage through
logs is canon — covered by `/gsd-secure-phase`, `make audit` and the existing `BearerToken` redaction
convention; not minted here."
