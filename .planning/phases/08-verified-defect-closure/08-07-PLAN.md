<objective>
Make a library-only build genuinely library-only: migrate `src/main.rs` off `structopt` to the
already-vendored `clap` v4, gate the `paladin` binary behind `required-features = ["cli"]`, give
`paladin-herald` its first `[features]` section so `colored` and `comfy-table` stop entering a
default build through Herald, and gate the three root-facade sites that would otherwise fail to
compile.

Purpose: ROADMAP criterion 4 requires that a downstream project depending on `paladin` compile no
CLI crates. Today the shipped `cli` feature isolates 5 of 8 CLI-only dependencies while `structopt`,
`colored` and `comfy-table` remain unconditional root dependencies — the one place in this corpus
where the checkboxes *overstate* completion. ADR-0023 (plan 08-04) records the decision; this plan
executes its `must change`.

This is the phase's largest and riskiest item, and it is larger than CONTEXT.md scoped it: research
found two root-facade files D-14 did not name, and planning found a third. Miss any one and
`cargo build --lib --no-default-features` fails to compile, so criterion 4's `cargo tree` never runs.

Output: `structopt` gone from the tree; the three `[[bin]]` targets consistent; Herald's styled
formatters behind features; the default library build compiling with zero CLI dependencies.
</objective>
