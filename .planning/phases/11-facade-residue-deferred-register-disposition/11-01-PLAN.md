<objective>
Record a per-occurrence disposition for every one of D5's 17 `println!`/`eprintln!`/`dbg!`
occurrences as deliberate rustdoc-example stdout, and correct the misleading "quick win / runtime
residue" framing at both of its sources — `deferred-items.md`'s D5 clause and ROADMAP §Phase 11
criterion 1.

Purpose: FACADE-01's premise is inverted. The register's *count* is exact and its *characterisation*
is wrong — all 17 lines are `///` or `//!` doc-comment lines inside fenced code blocks, so converting
them to `log::*` would degrade the documentation rather than improve hygiene (D-01). Leaving either
source uncorrected keeps asserting that runtime stdout exists in library code and forces the next
reader to re-derive this finding from scratch.

Output: a new `.planning/` register holding all 17 dispositions plus the Phase 15 hand-off; a dated
Shape-A correction on `deferred-items.md`; an amended ROADMAP criterion 1; an amended ledger row.

**This plan is the phase's tracer.** Task 1 carries one requirement through every record layer this
phase has — new `.planning/` register → `.project/` source annotation → governing-document amendment
→ existing ledger row — with every citation re-measured against the working tree, and commits it,
before FACADE-02/03/04 fan out in wave 2 and replicate the same convention. The ADR layer is
deliberately absent from the tracer: D-14 rules FACADE-01 not contested and therefore explicitly not
ADR material, and manufacturing an ADR nobody disputes is the exact outcome D-14 rejects. Task 2
gates that layer instead.

This plan writes records, not executable code. The boundaries that matter are provenance boundaries —
where a claim crosses from a lower-trust source into a higher-trust one.

| Boundary | Description |
|----------|-------------|
| working tree → `.planning/` record | A measured fact (a grep count, a `file:line`) becomes a durable assertion that later phases treat as settled without re-measuring |
| `.project/` historical corpus → `.planning/` governing record | A Milestone-8-era claim is promoted, corrected or superseded; the corpus document is known-fallible (this plan proves one of its claims wrong) |
