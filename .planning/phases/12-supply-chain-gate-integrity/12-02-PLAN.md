<objective>
Build the D-08 regression guard: a small offline script that fails if an advisory-ignore flag ever
reappears on a `cargo audit` or `cargo deny` invocation in a workflow file, wired into the two places
the existing guards are already wired.

Purpose: this is what turns ADR-0036 from an observation into a gate. Today's enforcement has a hole —
`check-advisory-register.sh` asserts that the register, `deny.toml`, `.cargo/audit.toml` and
`Cargo.lock` agree, but nothing anywhere asserts that a workflow file carries no inline advisory
suppression. The exact defect SUPPLY-01 existed to fix could be reintroduced tomorrow and every gate
would stay green. An ADR alone is prose, and prose did not stop the duplicate job the first time.

Output: `scripts/check-workflow-suppressions.sh`, a `check-workflow-suppressions` Makefile target in
the `check-gates` aggregate, one `ci.yml` step in the `cargo-deny:` job, and a demonstrated
positive/negative test pair run against the script itself rather than against an extracted regex.
</objective>

`scripts/check-advisory-register.sh`, or a sibling script. **This plan chooses a sibling script**, for
two reasons: every existing clause in `check-advisory-register.sh` parses TOML with `tomllib`, and a
clause that parses YAML would put two parsers in one heredoc against that script's single stated

positive test needs a root-directory override, which is an addition to the new guard's contract and
would otherwise be a change to a script three phases already depend on. Both layouts satisfy D-08's
fixed constraints; this one keeps each script's responsibility single. Record this rationale in the
SUMMARY.

**Header comment.** State the same four properties its analog states, in this guard's own terms: it is
offline and makes no network call; it parses workflow YAML structurally with `PyYAML` and never scrapes
raw file text or comment prose to decide whether a command is a suppression; it reports every violation
rather than stopping at the first; and it only reads — writes nothing and creates no temporary file, so
two consecutive runs over unchanged inputs produce identical output and the same exit code. State the
two clauses explicitly, state that matching is **case-sensitive** over the YAML-decoded string and why,
and close with the `Usage:` and `Exit:` block in the analog's format — noting that the optional first
positional argument overrides the scanned directory and exists so the guard's own positive test can run
against a scratch copy without ever mutating the real tree.

**Bash wrapper.** `#!/usr/bin/env bash`, then `set -euo pipefail`. Derive
`WORKSPACE_ROOT` from `BASH_SOURCE` exactly as the three siblings do. Then define `WORKFLOWS_DIR`
defaulting to the workflows directory under `WORKSPACE_ROOT` and overridable by the first positional
argument. Guard on `command -v python3` with a named `ERROR:` message and a non-zero exit, matching the
analog's wording. Emit the magnifying-glass `Checking …` status line once at the start. Run the Python
logic in a **single-quoted** heredoc so the ignore-flag pattern's end-of-string anchor is not expanded
by the shell. Read only the first line of Python's stdout into `STATUS_LINE` and the remainder into
`DETAIL`; on `OK` print the check-mark summary and exit `0`, otherwise print the cross-mark failure
line, the accumulated detail, and numbered remediation guidance — three items: put the advisory in
`.cargo/audit.toml` or `deny.toml` and add its register row rather than passing a flag inline; if a
second `cargo audit` invocation was added deliberately, it is the duplicate-job defect SUPPLY-01
closed, so remove it; and if the guard is wrong about a command, fix the guard rather than the
workflow. Exit `1`.

**Python logic.** Import `sys`, `re`, `glob`, `os` and `yaml`. Take the scan directory from `sys.argv`.

  - Collect files by globbing both `*.yml` and `*.yaml` under the scan directory, sorted, so a future
    workflow file cannot introduce a suppression the guard never looks at and so report order is
    deterministic. If the glob yields zero files, append a named failure and stop — a silently-empty
    comparison that reports success over nothing is its own defect, exactly as the analog treats a
    missing input file.
  - Parse each file with `yaml.safe_load`. Walk `jobs.*.steps[]` and collect every `run` value that is a
    string, keeping the file path and the job/step identity alongside it for the report. Tolerate a
    file that parses to `None`, a job without `steps`, and a step without `run` — each is a clean
    absence, not an error. A file that fails to parse is a named failure, not a skip.
  - Normalise each collected `run` string before matching: join backslash-continuations (a trailing
    backslash followed by a newline becomes a single logical line), then split on newlines and strip.
    **Match per logical line, not per whole block** — otherwise a `run: |` block containing
    `cargo audit` on one line and an unrelated `--ignore-existing` command on another would
    false-positive.
  - Define `CARGO_GATE_RE` as the pattern matching a word-bounded `cargo`, whitespace, then `audit` or
    `deny` word-bounded. Define `IGNORE_FLAG_RE` as the pattern matching `--ignore` followed by a space,
    an equals sign, or end-of-string. The trailing-character requirement is deliberate and is what
    excludes `--ignore-existing` (followed by a hyphen) and `--ignored` (followed by a `d`) — a
    word-boundary assertion would **not** exclude `--ignore-existing`, because the transition from `e`
    to `-` is itself a word boundary. Define `violates(line)` as both patterns matching the same logical
    line. The co-occurrence requirement is the primary defence and the flag pattern's precision is the
    second layer: both known false-positive tokens fail the `cargo audit`/`cargo deny` half before the
    flag pattern is consulted at all.
  - **Clause 1** — for every logical line where `violates` is true, append a failure prefixed
    `CLAUSE1_INLINE_SUPPRESSION` naming the file, the job, the step and the offending line. Do not stop
    at the first.
  - **Clause 2** — count logical lines matching a word-bounded `cargo` + whitespace + `audit` across the
    whole collected corpus. If the count is not exactly `1`, append a failure prefixed
    `CLAUSE2_AUDIT_INVOCATION_COUNT` naming the count and every file and line where a match occurred.
    Note in a code comment near this clause why `cargo install cargo-audit` does not count: the pattern
    requires whitespace between the two words, and the installed binary's name is hyphenated.
  - Accumulate both clauses into one shared `failures` list and only decide the verdict after both have
    run. Print `OK` plus a one-line summary naming the number of workflow files scanned, the number of
    `run` steps examined and the `cargo audit` invocation count; or print a status token and every
    accumulated failure, sorted by file path then by position, so two runs produce byte-identical
