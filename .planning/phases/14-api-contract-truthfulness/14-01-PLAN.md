<objective>
Rename the agent API's token vocabulary, end-to-end through every code layer, so the contract the
project publishes matches the mechanism it runs (WEB-01). D-01 ratified opaque server-issued bearer
tokens as the mechanism; this plan applies D-02 (config key, clean break, no alias), D-03 (OpenAPI
security scheme and its format hint), D-04 (the public Rust field and its CHANGELOG break) and D-05
(the correction reaches every named surface), regenerating both machine baselines in the same commits
that move them per D-20.

The plan leads with a `checkpoint:decision` because the replacement identifiers are Claude's
Discretion and are a published-contract choice no human has ratified, then a single `tracer` task that
drives the rename through config -> binary wiring -> web middleware -> published contract -> both
baselines in one compiling, test-green commit. A partial rename does not compile, so the layers cannot
be split; the tracer is the thinnest slice that is also the only viable one.

Purpose: close the only variant in five verification runs that shipped code could not settle — the
tree carrying the Milestone 12 vocabulary and the Milestone 9 mechanism at once.
Output: one token vocabulary across five Rust files, four non-Rust surfaces, two regenerated machine
baselines and two BREAKING changelog entries.
</objective>
