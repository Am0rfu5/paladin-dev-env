<objective>
Land the release bookkeeping D-17 assigns to this phase and close D-18's ordering trap.

This phase shipped two consumer breaks — the config key renamed with no alias, and a published crate's
public field renamed — so under SemVer for `0.x` the version bumps the **minor**: 0.7.0 to **0.8.0**,
not 0.7.2. Shipping two renames under a patch version would be the same class of untruth the phase
exists to close. `release.toml` sets `shared-version = true`, so all twelve manifests move together.

D-18 is the trap this plan exists to close. The OpenAPI decorator sources the document's advertised
version from the crate version, so the bump moves the committed baseline a **second** time — after
plan 14-01's security-scheme rename already moved it once. A phase that regenerates only after the
rename leaves the drift guard red. This plan regenerates after the bump and then verifies the guard in
its **checking** mode with the update flag unset, which is the only proof the baseline is actually
correct rather than merely freshly written.

Purpose: the phase ends with one version, one contract, and both guards green.
Output: twelve bumped manifests, a refreshed lockfile, a dated changelog section, and a regenerated
published contract.
</objective>
