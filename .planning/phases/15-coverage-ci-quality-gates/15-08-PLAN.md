  <files>src/application/services/orchestration/listener.rs</files>
  <action>
    Extend the existing `#[cfg(test)] mod tests` in place. Extend the in-module `MockEventListener`
    rather than adding a second fake: give it configurable `should_process` behaviour and a
    configurable `health_check` result, keeping its existing construction sites working. Touch nothing
    above the `#[cfg(test)]` marker.

    **Registration and lifecycle.** Registering a listener whose name is already registered — assert
    the actual verdict, replace or reject, rather than presuming one. Unregistering a listener that
    was never registered — assert the defined result, not a panic. Unregistering a registered listener
    removes it from `list_listeners` and from `get_all_stats`. `set_listener_enabled` in both
    directions, with the effect asserted by processing an event afterwards and observing whether a
    trigger was produced — not by reading the flag back.

    **Delivery and filtering, with ordering.** A matching event produces exactly one trigger. A
    non-matching event produces none — use the factory's deliberately-non-matching constructor so the
    near-miss is precise. A fan-out event matching three registered listeners produces three triggers,
    one per listener; assert the set of producing listeners rather than only the count. Then assert
    whatever ordering guarantee the implementation actually provides for the trigger queue: read
    `process_event` and `get_next_trigger` and pin down the real behaviour. If no ordering guarantee
    exists, assert set membership rather than order, and record the absent guarantee in the scope
    block — do not write an order-dependent assertion that will flake under load.

    **The rate-limit boundary.** Configure a listener with a known rate limit and drive events at
    exactly the limit, one below and one above, asserting the verdict at each of the three points.
    Use `tokio::time::pause()` and `tokio::time::advance()` for any window-dependent step; a
    wall-clock wait makes the test's verdict depend on runner speed, which is a test that lies rather
    than one that flakes honestly.

    **Trigger expiry.** `cleanup_expired_triggers` exercised at the expiry boundary and one step
    either side, again under paused time. Assert the queue length before and after.

    **Trigger status tracking and retry.** `get_trigger` for a known id and for an unknown id;
    `update_trigger_status` across each `TriggerStatus` transition the type supports, with the new
    status read back through `get_trigger` or `get_trigger_summaries`; a retry transition asserted for
    whatever the implementation does to the retry count.

    **Idempotency.** Process the same event twice and assert the observed outcome — whether a second
    trigger is produced or the event is deduplicated. Assert what the code does; do not presume a
    guarantee.

    **Statistics and health.** `get_listener_stats` for a known and an unknown listener;
    `get_all_stats` reflecting counts after N processed events; `trigger_queue_length` before and
    after processing; `health_check` with all listeners healthy, with one unhealthy, and with none
    registered, asserting the map contents rather than only its size.

    Every test asserts on behaviour. A call with no assertion about its result raises the number and
    proves nothing, which is the failure this phase exists to end. Reuse the existing test-naming
    style in this module.
  </action>
