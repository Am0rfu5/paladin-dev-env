deliberately removed.

**D-09b** is the half of SC1 that remains. The mechanical trigger repair is already merged; what was
missing is the recorded policy and something that notices when it drifts. The table records workflow,
triggers, push branch filter and rationale, one row per workflow file. The script parses every
workflow's trigger block structurally and fails on two conditions: a workflow with no table row, and
a recorded row that disagrees with the YAML. The case it actually catches is a *new* workflow added
with no policy entry, or a branch filter quietly reintroduced — the workflow linter validates syntax,
not intent, and nothing else in the repository would notice. The shape is the same register-plus-guard
pair the advisory register already uses and which was observed passing in CI.

**And the pre-existing gap is closed, not inherited.** The sibling guard's regression test exists,
is well built, and is wired only into a make target that **no workflow invokes** — so it has never run
in CI. This plan adds the CI step that runs both.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repository-committed YAML → guard script | The guard parses workflow files and a documentation table, both trusted-source but structurally untrusted input |
| Guard script → required check | The guard joins a job that gates every merge, so a defect in it blocks the repository |
| Policy register → enforcement | A human-editable table becomes the specification a machine checks against |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15.1-44 | Repudiation | A workflow silently stopping or a filter narrowing, with its absence read as nothing-to-report | high | mitigate | The register-plus-guard pair, applied to trigger governance exactly as it is already applied to advisory-suppression governance. The workflow linter validates syntax, not intent; only a policy table plus a checker can notice a workflow that *should* have an entry and does not. |
