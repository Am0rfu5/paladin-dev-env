## Planner decisions taken here (Claude's Discretion items, recorded with reasoning)

1. **Where the D-09 verdict record lives — a phase-directory artifact, not a ledger amendment.**
   `.planning/phases/16-.../16-DOCS-01-VERDICTS.md`. Fourteen evidence-bearing rows inlined into
   `REQUIREMENTS.md` prose would scatter the record across a 3,400-line file and make "one artifact"
   (D-09) untrue in practice. `REQUIREMENTS.md`'s DOCS-01 entry gets a **pointer** to it at phase
   close (plan 16-05), which is the ledger half without the scattering.
2. **Plan splitting for the fourteen — five plans, one shared record.** D-09 fixes the *artifact* as
   single; it does not fix the *plan count*. 10,337 lines of markdown is ~130k tokens of reading;
   one sweep plan would blow the context budget and degrade exactly the careful reading D-12 asks
   for. Split by directory group (16-01 cicd, 16-02/16-03 user-guides, 16-04 deployment, 16-05
   operations), each appending to the one record. Because they share that file they are **sequential
   waves by construction** — a same-wave pair would clobber each other's rows.
3. **`mdbook-mermaid install docs/` is not re-run.** `docs/mermaid.min.js` and `docs/mermaid-init.js`
   already exist locally and are `.gitignore`d (`.gitignore:21-22`); `docs/book.toml` already carries
   the preprocessor and `additional-js` entries. Re-running it can only produce a spurious
   `book.toml` diff. Run it only if either asset is missing, and assert `book.toml` is unchanged.

## The DOCS-01 signal battery (defined once, reused by 16-02 … 16-05)

Eight checkable signal classes, one command each. Every sweep plan runs the full battery per file
and pastes the producing command into the row. **Class 3 carries M-06's warning: most `paladin-*`
tokens in `kubernetes.md` are Kubernetes object names, not crate names — classify each hit before
acting on it.**

| # | Signal class | Producing command (per file `F`) | Compared against |
|---|---|---|---|
| 1 | version strings | `grep -nE 'v?[0-9]+\.[0-9]+\.[0-9]+' "$F"` | root `Cargo.toml:34` (`0.8.0`) |
| 2 | dependency pins | `grep -nE '^[a-z-]+ *= *\{? *version' "$F"` | that crate's `Cargo.toml` |
| 3 | crate names | `grep -noE 'paladin-[a-z-]+' "$F" \| sort -u` | `ls crates/` — **classify vs k8s object names first** |
| 4 | module / source paths | `grep -noE '(crates\|src)/[A-Za-z0-9_/.-]+\.rs' "$F"` | `test -f` each path |
| 5 | `make` targets | `grep -noE 'make [a-z-]+' "$F"` | `grep -oE '^[a-z-]+:' Makefile` |
| 6 | workflow / job names | `grep -noE '[a-z-]+\.yml' "$F"` and quoted `jobs:` ids | `ls .github/workflows/` + each file's `jobs:` block |
| 7 | error types | `grep -noE '[A-Z][A-Za-z]*Error(::[A-Za-z]+)?' "$F"` | `grep -rn` in `crates/` and `src/` |
| 8 | feature flags | `grep -noE -- '--features [a-z0-9,_-]+\|feature = "[a-z0-9_-]+"' "$F"` | the relevant `[features]` block |
| — | prose | read end to end | statements the 0.8.0 tree contradicts |
