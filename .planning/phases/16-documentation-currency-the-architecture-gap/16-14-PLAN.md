<objective>
Close DOCS-04: record the four demos, index them, link them from the README with one line, and amend
the two premises in the requirement's own text that this phase measured false.

Purpose: DOCS-04 asks for a **decision** with the reason on record, and for `docs/assets/` to stop
implying work in flight. The decision (D-13) is to record — because the stated blocker is measured false.
All four named scenarios have shipped examples that run on mock adapters offline: `cargo run --example
basic_paladin` was verified end to end at exit 0 with no credentials (M-08). Withdrawing on a premise
that is untrue would close the requirement dishonestly.
Output: four `.tape` sources with their `.gif` and `.cast` artifacts, `docs/DEMOS.md`, one README
line, and two dated in-place requirement amendments.

**Discretion decisions taken here, recorded with reasoning:**

1. **No CI regeneration check for the `.tape` scripts.** VHS needs `ttyd` and `ffmpeg` on the runner,
   and GIF encoding is not byte-deterministic across runs — frame timing and quantisation vary — so a
   regeneration-and-diff gate would be permanently flaky, and a flaky required check trains people to
   ignore it. D-08 also declines adding gates in this phase. Instead each demo's exact regeneration
   command is recorded next to it in `docs/DEMOS.md`, so regeneration is a documented one-liner rather
   than an unwritten ritual, and the structural invariant (every `.tape` has a matching `.gif` and
   `.cast`, and names an example that exists) is asserted in this plan's acceptance criteria.
2. **`docs/DEMOS.md` gets no `docs/src/SUMMARY.md` entry.** D-15 places the index at `docs/DEMOS.md`,
   which is **outside `docs/src/`** and therefore not part of the mdBook at all — it cannot have a
   `SUMMARY.md` entry. CONTEXT.md's Integration Points flagged this as needing a decision, so it is
   recorded rather than left implicit: the index is a repository-level page reached from the README,
   matching FR-26.4's own wording.

**Scope guards:** D-14 — VHS is the recorder of record and `.tape` is the source of truth; the
scripted `asciinema rec -c "<the same command the tape drives>"` produces the `.cast` VHS cannot emit,
from the identical underlying command. D-15 — the README gets **one line** and nothing else; the M11
Epic 5 landing page was deliberately made concise and is not to be re-inflated. D-16 — the four
scenarios and their example sources are fixed. D-00d — amend requirement text in place. D-00o —
commit with `--no-verify`.
</objective>

**not** put a `.cast` extension on a VHS `Output` line: VHS does not reliably error on an unrecognised
extension, so a tape written that way can appear to succeed while producing nothing usable.

**Nothing is hand-performed.** No frame editing, no re-typing output by hand, no compositing. If a
recording looks wrong, fix the `.tape` and re-run it. A hand-made take is stale documentation with
extra steps — which is the whole reason D-14 chose a scripted recorder in a phase about documentation
that stays current.

Before committing any binary: play back or parse each artifact and confirm it is complete and shows
the real output, that no credential or key appears on screen, and that each file is within the size
budget recorded in `16-DOCS-04-TOOLCHAIN.md`. A file over budget is re-recorded at a smaller width,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local terminal session → committed recording | Whatever is on screen during a recording is captured verbatim and committed permanently. |
| committed binary → git history | A `.gif` in history is not removable without a history rewrite; this is why the size budget was decided in 16-13, before any binary existed. |
| `docs/assets/` vs `docs/src/assets/` | Two different paths one level apart; one is new and owned by this plan, the other holds six pre-existing architecture SVGs owned by DOCS-02. |
| README + demo index → every reader | The index is what a reader trusts to describe what the framework actually does. |
