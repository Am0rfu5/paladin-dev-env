## Resolved open questions (decided here, not inherited)

RESEARCH.md left three open questions. Two are disposed of by this plan; the third by 17-07.

1. **Mock-transport test placement — DECIDED: crate-local.** `mockito` is added as a
   `paladin-llm` dev-dependency and every provider's request-shaping / response-parsing /
   streaming / error-mapping tests live in that provider's own `#[cfg(test)]` module, beside the
   adapter code. Rationale: it matches the crate's existing "one directory per provider, tests
   in-file" convention, and it keeps a preset's tests runnable under
   `cargo test -p paladin-llm --no-default-features --features <provider>`, which a workspace-level
   `tests/integration/` file cannot do (a root-level test target compiles whatever the facade's
   feature graph gives it). `mockito` is already a vetted root dev-dependency
   (root `Cargo.toml:143`, version `1.7.0`); pin the same version.
2. **Retry parity for a local Ollama endpoint — DECIDED: no per-provider fork.** The engine's
   single `call_api_with_retry` policy applies unchanged to every preset including Ollama. A
   second, "local endpoints retry less" policy is a time-dependent code path with its own tests for
   no observed benefit, and RESEARCH.md's "Don't Hand-Roll" table names the retryable-error-SET
   drifting out of lockstep as the exact bug class the shared engine exists to prevent.
3. **Where the core lives — DECIDED: `crates/paladin-llm/src/compat/`.** Inside `paladin-llm`, not
   a new crate (Claude's Discretion in 17-CONTEXT.md). ADR-0035's leaf-crate precedent is scoped to
   an ML adapter and does not bind LLM providers; a new crate would add a workspace member and a
   `cargo tree --no-default-features` edge for zero benefit (ADR-0031, D-00s).

**`crates/paladin-llm/src/redaction.rs`** (NEW, crate-level, **not** feature-gated) — the
credential-redaction trio, lifted from the DeepSeek adapter's `:250-356` block:
`redact_credentials` (three passes: configured key exact match, bearer-scheme prefix, `sk-` prefixed

secret in half and leak the surviving prefix. Bound by `char` count, not byte count, so truncation
cannot split a multi-byte UTF-8 sequence. `RESPONSE_EXCERPT_CHAR_BUDGET` lives here.

This module is deliberately **outside** `compat/` and carries no `#[cfg(feature = ...)]` gate,
because the bespoke Gemini adapter (plan 17-05) must reuse it without depending on the compatible
core. Redaction correctness is security-critical; one implementation, one set of tests. Declare it
in `lib.rs` as `pub(crate) mod redaction;` (or `pub mod` with full rustdoc if any of its items need
to be public) and port the DeepSeek adapter's existing redaction tests across so the behaviour is
covered from the first commit.
