<objective>
Make the facade's LLM feature flags real, and extend the configuration surface to the nine providers
that now exist — without breaking a single existing config file.

Root `Cargo.toml` declares `llm-openai = []`, `llm-anthropic = []` and `llm-deepseek = []` as empty
stubs while pulling `paladin-llm` in at line 55 with
`features = ["openai", "anthropic", "deepseek", "mock", "vision"]` **unconditionally**. Every build
today compiles all three providers regardless of what the flags say, so PROJECT.md's documented
compile-time contract — "unavailable adapters must fail at compile time, never at runtime" — is not
what ships. D-11 repairs it and accepts the consequence: **a default build stops silently including
Anthropic and DeepSeek.**

**Purpose:** PROV-03's whole premise is that adapters are feature-gated and additive. Adding five
providers to a flag system that gates nothing would ship five more inert flags and make the defect
five times harder to explain. D-11 rejected leaving the existing three as stubs while wiring only
the new five: two classes of flag, some real and some inert, is harder to explain than either end
state.

**Output:** a rewired root feature graph, ADR-0046, a `BREAKING` CHANGELOG entry, and an `LlmConfig`
that accepts all nine providers while still loading every config file that works today.

**Scope guards:**
- **D-00n** — the project is at 0.8.0 with `shared-version = true`; pre-1.0 semantics (ADR-0008)
  absorb a breaking change as a minor bump. That is what makes D-11 affordable; say so in the ADR.
- **D-00s / ADR-0031** — nothing here may create a leaf-to-leaf or facade edge in a default build;
  the change removes dependency features, it does not add dependencies.
- **D-06** — no shipped adapter's code changes. Only the manifest, the changelog, the ADR and the
  config surface.
- **D-00o** — commit with `--no-verify`. This plan necessarily touches the root manifest, so a
  `cargo check` at the workspace level is unavoidable for one acceptance criterion; prefer
  `cargo tree`/`cargo metadata` (which do not compile) wherever they can answer the question, and
  run at most one `cargo check --no-default-features` at plan close rather than per task.
</objective>

## Decision resolved in this plan

**Config surface shape (Claude's Discretion in 17-CONTEXT.md) — DECIDED: six additional named
fields, not a map.** `LlmConfig` today is a struct with one `Option<LlmProviderConfig>` field per
provider and hardcoded match arms in `validate()` and `get_provider_config()`. Restructuring to a
`HashMap<String, LlmProviderConfig>` is the tidier end state, but it changes the serialized shape of
a type that already appears in operators' `config.yml` files and in `LlmConfig::default()`, and
PROV-03's binding constraint is that existing config files keep loading. Six more named fields is
repetitive and boring and does not risk that. The registry-derived `provider_names()` from plan
17-01 is used to validate `default_provider` so the *name set* has one source even though the
*field set* is hand-written; that captures most of the benefit of a map with none of the
compatibility risk. Record the repetition as a known cost in the SUMMARY, not as a defect.

  <context>
    **D-11 is locked and is not being re-asked as a principle.** The human decided in the
    2026-08-16 `/gsd-discuss-phase 17` session that the facade's `llm-*` flags are wired for real,
    rated it **one-way**, and accepted a `BREAKING` CHANGELOG entry. What this checkpoint confirms
    is the one remaining lever: the **default flag set**, which decides whether the break is
    observable to a consumer who never touches features.

    The measured facts: root `Cargo.toml` sets `default = ["llm-openai"]`; `llm-openai`,

    `features = ["openai", "anthropic", "deepseek", "mock", "vision"]` on the `paladin-llm` path
    dependency unconditionally. So today a default build compiles three providers while declaring
    one. After the flags are wired, `default = ["llm-openai"]` compiles exactly one.

    Undo cost, which is why this is one-way rather than costly: it changes what a default build
    contains for every consumer. Reversing it later is a second breaking change, not a revert. The
    project is pre-1.0 at 0.8.0 with `shared-version = true`, so ADR-0008's semantics absorb it as a
    minor bump (D-00n) — but the consumer-visible break is real regardless of how the version number
    is spelled.
  </context>

Every consumer who relied on Anthropic or DeepSeek being silently present learns it now, from a CHANGELOG entry, rather than at some later moment.       <cons>Preserves a default build that compiles three providers when the project's stated posture is opt-in adapters, so the "unavailable adapters fail at compile time" contract stays half-true by accident of the default set. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator `config.yml` → adapter configuration | Provider blocks including `api_key` cross from a file on disk into adapter construction. |
| Build configuration → what code exists in the binary | The feature graph decides which adapters are compiled in at all; a flag that gates nothing means the binary contains more attack surface than its build declares. |
| Published CHANGELOG → consumer expectations | A silent behaviour change in a default build is a repudiation risk: the project would be shipping a break it did not announce. |
