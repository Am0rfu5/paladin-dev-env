## Decision resolved in this plan (RESEARCH.md Open Question 3)

**Extend `capability_invariants` to the new adapters — DECIDED: yes, as a sibling module.**

The existing module (`crates/paladin-llm/src/lib.rs`, gated on
`all(test, feature = "openai", feature = "anthropic", feature = "deepseek")`) permanently pins the
tool-calling / function-calling correspondence for the shipped three. 17-CONTEXT.md does not mention
it at all — that is an omission, not a deliberate exclusion, and leaving it would mean the six new
adapters carry the truthfulness standard only in prose. A **sibling** module gated on the new
feature set is preferred over widening the existing gate, because widening would make the shipped
three's invariant stop compiling unless every new feature is also enabled, which would silently
disable a test that runs today.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → `ollama/ollama` container image | A third-party image is pulled and executed in the test environment; it serves an HTTP endpoint the test suite talks to. |
| Test process → Docker service network | `OLLAMA_TEST_URL` points the adapter at a container; the suite runs with no credential, so no secret crosses this boundary. |
| Coverage measurement → the phase's completion claim | A coverage figure obtained with a suite silently skipped means something different from one obtained with it run. |
