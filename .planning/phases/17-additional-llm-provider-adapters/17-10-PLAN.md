<objective>
Close **WR-04**: Kimi, Qwen, Grok, Ollama and Gemini all keep `reqwest`'s default follow-redirects
policy (up to 10 hops) despite each carrying an operator-settable `*_BASE_URL`, so a `3xx` from
whatever host that URL resolves to can replay the credential header to a different host.

`openai_compatible/adapter.rs` already mitigates exactly this correctly, with
`reqwest::redirect::Policy::none()` and a documented trust-boundary section (T-17-18). **That
mitigation is the pattern to reuse verbatim — not a second design.**

**Purpose:** WR-04 is not only a missing mitigation, it is a *wrong comment*. Each of the four
compat presets carries an in-code rationale asserting its endpoint is "a fixed vendor host, not
operator-supplied", which is factually false for all four — `MOONSHOT_BASE_URL`,
`DASHSCOPE_BASE_URL`, `XAI_BASE_URL`, `OLLAMA_BASE_URL` and `GEMINI_BASE_URL` are each documented
and settable. A future maintainer auditing this exact threat would read that comment and conclude it
had been assessed. Correcting the comment is half the fix.

**Output:** `Policy::none()` on all five adapters, four corrected comments, one actionable
refused-redirect error arm per error mapper, and behavioral proof on both client-construction paths
(the shared `CompatEngine` and Gemini's bespoke `Client`).

## Where the fix lives, and why — recorded deliberately

Two placements were available. The fix goes **per-adapter**, and this is the reasoning:

1. **Reuse over reinvention.** The brief and the review both name
   `openai_compatible/adapter.rs`'s mitigation as the reference implementation. It sets
   `redirect_policy: Some(reqwest::redirect::Policy::none())` at the preset, not in the engine.
   Copying that line into four siblings reuses a shipped, reviewed pattern; inverting the engine's
   default would introduce a *second* mechanism alongside it.
2. **The engine's field semantics stay honest.** `CompatEngineConfig.redirect_policy` is a `pub`
   field on a `pub mod compat` type, documented as *"`None` preserves this engine's original
   behaviour — `reqwest`'s own default policy"*. Making `None` mean *deny* would be a silent
   semantic inversion with no signature change — invisible to the `api-surface` guard, invisible in
   a diff of the presets, and exactly the kind of change that is hard to audit later. It would also
   remove any way for a future preset to legitimately follow a redirect.
3. **The diff touches those four files regardless.** WR-04 names the four wrong comments as part of
   the defect. Centralizing in the engine would save zero files while still leaving four inaccurate
   rationales in place.
4. **Gemini cannot be covered by the engine at all.** It builds its own `reqwest::Client` (D-08), so
   an engine-side fix would still need a second, per-adapter change — two mechanisms instead of one.

The cost accepted by this choice: a hypothetical sixth preset could forget the line. It is mitigated
by the source assertion in this plan's acceptance criteria (all five presets carry the identical
literal) and by each preset's corrected comment now naming the threat explicitly rather than denying
it.
