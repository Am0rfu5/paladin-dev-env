<objective>
Close **G-17-4a**: Grok cannot complete a single `generate()` call against any current xAI model.

The measured cause is not a stale model ID. `CompatEngine::build_request` serialises
`presence_penalty` unconditionally, sourced from `PromptParameters::default()`
(`paladin-core` prompt.rs:154 sets `Some(0.0)`), so it is on the wire for every request. xAI
rejects the **parameter's presence** for every current model — `grok-4`, `grok-4.6`, `grok-4.5`
and `grok-4.3` all return
`{"code":"invalid-argument","error":"Model <m> does not support parameter presencePenalty."}`.
Refreshing the model ID alone changes nothing.

This is the **tracer** for the gap-closure run: it wires one thin path through every layer the
run touches — a preset's declaration, the shared engine's request shaping, the wire body, the
real vendor, and a live harness that can tell a pass from a vacuous pass — and proves it
end-to-end against `api.x.ai` before plan 17-19 expands the same seam to Kimi's temperature
constraint.

**Purpose:** make the xAI preset functional out of the box, using a mechanism the next vendor
quirk can reuse without editing the shared engine.
**Output:** `CompatRequestParameters` on the engine config, an xAI preset that declares what it
measured, refreshed Grok model constants, and a smoke harness that exercises `generate()` — not
only `get_available_models()`.
</objective>

## Facts already established — read these, do not re-derive them

**`CompatEngineConfig` (compat/engine.rs:83-127)** is the preset→engine configuration struct and
is already the home of every per-vendor protocol knob: `fallback_models` (D-13's curated list),
`error_override` (a preset-specific status mapping that avoids editing the engine), and
`redirect_policy` (WR-04). The new parameter contract belongs **here**, beside them — not on
`CompatCapabilities`, whose every field maps one-to-one into the port type
`ProviderCapabilities` (`From<CompatCapabilities> for ProviderCapabilities`, engine.rs:67-80).
A field with no port-side counterpart would break that one-to-one correspondence.

**`CompatRequest` (compat/types.rs:14-28)** already carries
`#[serde(skip_serializing_if = "Option::is_none")]` on `temperature`, `max_tokens`, `top_p`,
`frequency_penalty` and `presence_penalty`. **"Not carried" is therefore already a first-class
wire state** — setting the field to `None` omits the JSON key entirely rather than emitting
`null`. No change to `types.rs` is needed and none is authorised by this plan.

**`build_request` (compat/engine.rs:196-210)** reads
`request.prompt.node.node.parameters` and copies all five straight through. This is the single
site that decides the outgoing body for all six compatible presets.

**Five construction sites** must be updated when `CompatEngineConfig` gains a field —
`grok/adapter.rs:152`, `kimi/adapter.rs:152`, `qwen/adapter.rs:163`, `ollama/adapter.rs:173`,
`openai_compatible/adapter.rs:529` — plus the two test helpers `test_config()`
(engine.rs:717) and, transitively, `test_config_at()` (engine.rs:970).

**`ProviderCapabilities::temperature_range` is out of scope for this plan.** It is governed by
ADR-0004 and its interaction with a fixed-temperature vendor is plan 17-19's decision
checkpoint. Declare `temperature: true` for every preset here and change nothing about
temperature behaviour.

**The harness discriminates a live fetch from the curated fallback** by comparing the returned
list byte-for-byte against the preset's `*_FALLBACK_MODELS` constant
(`live_vendor_smoke.rs:51-60`). Preserve that discrimination exactly; the generate probe is
**additional** reporting, not a replacement.

**Credentials** arrive from a host bind-mount. A non-interactive shell must source
`/workspace/.devcontainer/paladin-env.sh` **directly** — never through a pipe, which runs it in
a subshell and discards the exports. `paladin-keys` then reports which resolved, without
printing any value.

1. **Commit with `git commit --no-verify`.** `workflow.worktree_skip_hooks` is `true` in
   `.planning/config.json` (D-00o); without `--no-verify` the pre-commit hook cold-compiles the

   ```bash

   ```

   `. script | head` runs the script in a subshell and silently discards every export — the

   ```bash
   MODEL=<a model id confirmed present in the live list>
   for P in '"temperature":0.7' '"max_tokens":16' '"top_p":1.0' \
            '"frequency_penalty":0.0' '"presence_penalty":0.0'; do
     echo "=== $P"
     printf 'header = "Authorization: Bearer %s"\n' "$XAI_API_KEY" \
     | curl -s --config - \
         -H 'Content-Type: application/json' \
         -d "{\"model\":\"$MODEL\",\"messages\":[{\"role\":\"user\",\"content\":\"ping\"}],$P}" \
         https://api.x.ai/v1/chat/completions \
     | head -c 400
     echo
   done
   ```

   Inspect each response before quoting it into the SUMMARY; quote only the error envelope.
4. **The live model list, without a generate call:**

   ```bash
   printf 'header = "Authorization: Bearer %s"\n' "$XAI_API_KEY" \
   | curl -s --config - https://api.x.ai/v1/models
   ```


<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Paladin process → vendor API (`api.x.ai`) | The `Authorization` header carries the operator's credential across this boundary on every request, and the untrusted response body comes back across it. |
| vendor response body → logs / SUMMARY / test output | A vendor error body is attacker-influenceable text that this plan deliberately quotes into a durable record. |
| preset declaration → shared engine → wire body | One shared engine serves six vendors; a change to what it serialises reaches all six, not only the one being fixed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-74 | Information Disclosure | live probe commands and harness output | high | mitigate | This plan runs real credentialed requests and copies vendor output into a committed SUMMARY. Mitigations: the header is fed to `curl` through `--config -` so the key never enters the process argument list visible to `ps`; `set -x`/`curl -v` are prohibited; the harness prints only `LlmError` values, which the engine has already passed through `redaction::diagnostic_excerpt` (redact-then-bound, so a key cannot be sliced across the truncation boundary); every quoted body is manually inspected before it is written down. |
| T-17-75 | Tampering | `CompatEngine::build_request`, shared by six presets | high | mitigate | A mis-gated field would silently drop a parameter for **every** compatible provider — dropping `max_tokens` would remove the generation bound from all six at once, an unbounded-cost failure that no error surfaces. Mitigated by a behaviour-preservation test asserting that a preset declaring `all()` emits all five keys with the caller's exact values, by requiring all four non-Grok presets to declare `all()` in this plan, and by the absence of any `Default` impl, so no site can acquire a restriction by omission. |
