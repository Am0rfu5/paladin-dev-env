<objective>
Build the deliberate-vulnerability probe the adoption decision rests on, and make its scan path a
committed, re-runnable configuration rather than a one-off branch nobody can reproduce.

The fixture reuses the Snyk-era methodology verbatim — same four classes, same order — so the
resulting count is comparable to a number that already exists rather than to nothing. A fifth
defect sits behind a non-default cargo feature, because whether buildless Rust extraction reaches
feature-gated code has no documented answer anywhere and is this phase's central unverified risk.

Purpose: without a probe, adoption is vendor-claim-driven, which is exactly how the Snyk episode
happened.
Output: `fixtures/codeql-probe/` as a standalone workspace-excluded crate, the workspace exclusion
and secret-scanning accommodation that keep it inert, and the two CodeQL configurations that
separate the probe scan from the steady-state scan.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fixture crate → workspace build graph | Intentionally vulnerable code sits inside the repository; only the workspace exclusion and its location outside `crates/` keep it out of every build, lint and coverage run |
| fixture credential → repository secret scanning | A planted credential-shaped string crosses a required secret-scanning gate |
| fixture source → published crate artifacts | `cargo publish` packages files by directory; a fixture reachable from a published crate would ship vulnerable code to crates.io |
