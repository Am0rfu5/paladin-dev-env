<objective>
Give dismissed CodeQL alerts a governed home before the observation window starts producing them.

"Dismissed as a false positive" in a platform UI has no owner, no review date, no scope and no
compensating control — nothing a future auditor can query and nothing that expires. Left that way,
dismissal becomes the escape hatch that turns a green gate into assurance theatre, which is the
decay this phase exists to repair.

The shape is the one this repository already proved: a register carrying a prose explanation and a
machine-readable block, plus an offline guard that fails when the two disagree, wired into a
required check. The guard is scoped honestly — it validates the register's internal consistency
and staleness, and says out loud that it cannot reach the platform to confirm the live dismissal
set.

Purpose: SAST-03's promotion is only defensible if the alerts behind it are governed.
Output: `CODEQL-DISMISSALS.md`, `scripts/check-codeql-dismissals.sh`, its regression harness, a
make target folded into `check-gates`, and a step in the `License & Dependency Policy` job.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub alert store → committed register | The platform holds the live dismissal state; the register holds the governance metadata. The two are reconciled by a human command, not by the offline guard |
| register prose → register payload | The declared count and the structured rows are two statements of the same fact inside one file |
| guard output → reader's belief | A green guard run is read as "dismissals are governed"; scoping that claim correctly is itself a control |
