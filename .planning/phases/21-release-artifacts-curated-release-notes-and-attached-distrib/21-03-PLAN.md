<objective>
Invert the assembly order: create the release with the curated notes alone, then bind the
container image to it by immutable digest from a terminal job that reads what the run actually
produced.

Purpose: `build-docker` pushes multi-arch images and records nothing back — no digest, no tag
list, no link from the release to the image cut alongside it — while `Verify image size` emits a
warning above its 500 MB target and lets the run end green, which is the Phase 12 defect in a new
place. This plan closes ARTIFACT-04 and the composition half of ARTIFACT-03.

Output: `scripts/finalize-release-body.sh` (marker-based truncate-and-rebuild), its regression
harness, `build-docker` job outputs, and a new terminal `finalize-release-body` job.
</objective>

Create `scripts/finalize-release-body.sh` with the house header shape: purpose comment naming
ARTIFACT-03/ARTIFACT-04, an explicit `Usage`/`Output`/`Exit` contract block, `set -euo pipefail`,
a `FINALIZE_RELEASE_BODY_LIB_ONLY=1` sourcing seam exposing `finalize_release_body_main`, and a
`GH_BIN` (default `gh`) seam so the harness can stub the CLI.

Split the logic into two functions so the composition is testable without any network: a pure
`compose_release_body` that takes the curated text plus the artifact inputs and writes the full
new body to a path, and `finalize_release_body_main` that reads the current body, calls the
composer, and publishes.

Contract for this task: `--tag <vX.Y.Z>` (required), `--image-digest <value>` (optional),
`--image-ref <reference>` (optional), `--image-size-mb <integer>` (optional),
`--output <path>` (optional; default `${RUNNER_TEMP:-/tmp}/final-body.md`). An unrecognised flag
is a usage error. Plan 21-04 adds the asset/checksum/SBOM flags to the same contract.

Idempotency mechanism (the reason this is a script and not inline YAML): read the current body
with `$GH_BIN release view "$TAG" --json body -q .body`, then truncate at the fixed literal marker
`<!-- paladin:release-artifacts -->` using bash's longest-match trim (`${body%%"$MARKER"*}`) — no
`sed`/`awk` and no regex, so a curated section containing regex-special characters cannot perturb
the cut. If the marker is absent the whole body is the curated section and is kept in full. Then
rebuild: curated section, marker, a `---` rule, an `## Release Artifacts` heading, and the
sections in a fixed declared order. Never append to the existing artifact block; the body is
always rebuilt from current inputs, which is what makes both GitHub re-run shapes safe (Phase 20
D-03) and bounds the body against the ~125,000-character release-body cap.

Section rules for this task: emit a `### Container image` section only when both a digest and an
image reference are present, containing a fenced `docker pull <image-without-tag>@<digest>` line
and the pushed tag list; emit a `### Image size` line only when a size is present, stating the
measured whole-megabyte figure and whether it is within or over the 500 MB target, always as
advisory prose with no effect on the exit code. Normalise the digest exactly once: if the value
already begins with `sha256:` use it verbatim, otherwise prefix it — RESEARCH.md flags the wire
format as unconfirmed (Assumption A1), and this normalisation makes the script correct either
way. Derive the digest-pinned reference by stripping the tag suffix from the supplied image
reference, never by rebuilding it from the repository name. When no section input is present at
all, write a single line stating that no artifacts were recorded for this run rather than an
empty heading.

Publish with `$GH_BIN release edit "$TAG" --notes-file "$OUTPUT"` — the whole-body replace is
correct precisely because the body was rebuilt, and a non-2xx exit from `gh` is already a hard
failure so no status introspection is needed here.

  job's `needs`, and do not gate it on `test`: WR-05's documented asymmetry is preserved
  deliberately.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream job outputs → `finalize-release-body` `run:` body | Digest, tag JSON and size cross a job boundary into a shell step in a `contents: write` job |
| existing release body → composer → new release body | Text previously published (and hand-editable by a maintainer) is read back, cut, and rewritten |
| runner → api.github.com | Credential-bearing read-modify-write of the release object |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-10 | Tampering | `finalize-release-body` step | high | mitigate | Digest, image reference, tag JSON and size reach the `run:` body through `env:` only (CR-01); the composed body reaches the API as a file via `--notes-file`, never as an inline argument |
| T-21-11 | Tampering | truncate-and-rebuild over a maintainer-editable body | medium | mitigate | The cut uses a literal-string parameter-expansion trim, not a regex, so body text containing pattern metacharacters cannot move the truncation point; the double-marker case is asserted |
| T-21-12 | Denial of Service | release body growth across re-runs | high | mitigate | Rebuild-not-append bounds the body at (curated section + one fixed artifact block) regardless of re-run count, keeping it clear of the ~125,000-character cap that returns a hard 422 |
| T-21-13 | Spoofing | consumer pinning to a mutable tag | medium | mitigate | The body publishes the registry-issued immutable content digest and the exact tag list the run pushed; the reference is taken from `metadata-action`'s own JSON so a hand-built, never-tested reference cannot be published |
| T-21-14 | Repudiation | a failed artifact leg presented as complete | high | mitigate | The job runs under `if: always()` only to *omit* sections for non-successful legs; it never sets a leg's conclusion, and a failed upstream job remains red on the run |
| T-21-15 | Information Disclosure | `gh` calls in the finalize job | medium | mitigate | No `-L`/`--location` is passed; the job holds `contents: write` and nothing wider, and no secret is echoed into the composed body |
| T-21-SC | Tampering | package installs | low | accept | RESEARCH.md's Package Legitimacy Audit records **no new packages and no new Actions**; the new job uses only `actions/checkout@v4` (already in the workflow) and the runner-preinstalled `gh`/`jq` |
</threat_model>
