<objective>
Make the attached artifacts verifiable in one command, and say so in the release.

Purpose: per-asset `.sha256` files are produced today and explained nowhere, and the SBOM the
`sbom` job attaches is a single-package document presented without qualification. This plan closes
ARTIFACT-05 and the asset-inventory half of ARTIFACT-03: an aggregated `SHA256SUMS` covering
exactly what was uploaded, the one-command verification in the body, an asset list read from the
release itself, and the SBOM's real scope stated.

Output: checksum aggregation and the downloads/verification/SBOM sections in
`scripts/finalize-release-body.sh`, with matching harness coverage.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| published release assets → runner filesystem | The finalize job downloads artifacts it did not build into its own workspace |
| asset names → composed release body | Names originating from upload steps are rendered into consumer-facing markdown |
| runner → api.github.com / objects.githubusercontent.com | Credential-bearing download and upload from a `contents: write` job |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-16 | Tampering | asset substitution between build and consumer | high | mitigate | `SHA256SUMS` is generated from the bytes actually attached to the release (downloaded back from it), not from a build-time list, so it attests what a consumer will receive; the per-asset `.sha256` files produced on the building runner remain as an independent second record |
| T-21-17 | Spoofing | verification instructions naming a file the run did not attach | high | mitigate | The verification block is emitted only when aggregation actually attached a sums file, and the asset list is read back from the release rather than assembled from expectations |
| T-21-18 | Tampering | asset names rendered into markdown | medium | mitigate | Names reach the composer through a file, never through a command line; the composer writes them as list items and never evaluates them |
| T-21-19 | Information Disclosure | `gh release download`/`upload` following a redirect with a credential | medium | mitigate | No `-L`/`--location` is passed; the `gh` CLI owns its own credential scoping across the storage-host hop, and no hand-rolled `curl` transfer is introduced |
| T-21-20 | Repudiation | SBOM presented as covering more than it does | medium | mitigate | The body states the document's scope explicitly (root `paladin-ai` package), matching what `cargo cyclonedx --all` actually produced and what the job attached |
| T-21-21 | Denial of Service | unbounded asset download in the finalize job | low | accept | The pattern restricts the download to release archives whose count is bounded by the four-leg matrix; runner disk is ample for four tarballs |
| T-21-SC | Tampering | package installs | low | accept | RESEARCH.md's Package Legitimacy Audit records **no new packages and no new Actions**; aggregation uses runner-preinstalled `gh` and coreutils only |
</threat_model>
