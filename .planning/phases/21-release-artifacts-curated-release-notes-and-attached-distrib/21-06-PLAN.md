<objective>
Prove the artifact path end-to-end on a real throwaway tag, or record it as unverified.

Purpose: ARTIFACT-02's defect survived every previous reading of `release.yml` precisely because no
release since it was introduced was checked for the artifacts it claimed to attach. Success
criterion 7 is explicit that a workflow which is merely re-read and reasoned about does not satisfy
this phase. This plan runs the release for real on the next free prerelease version and records
what happened — including the two research assumptions only a live run can settle.

Output: `21-ARTIFACT-EVIDENCE.md`, following the `19-PUBLISH-EVIDENCE.md` /
`20-RECOVERY-EVIDENCE.md` shape.
</objective>

  <decision>Whether to cut a real throwaway tag on the current prerelease line to prove the artifact path, or to record the path as unverified.</decision>
  <context>
The rehearsal tag triggers the whole `release.yml` workflow — including `publish-crates`, which is
untouched by this phase and publishes all eleven workspace crates. That permanently occupies the
chosen release-candidate version on crates.io for every one of them: crates.io versions cannot be
deleted, only yanked, and yanking is a human act by the crate-owner account that this pipeline
must never automate. Phase 19 D-04 and Phase 20 D-14 established this cost as acceptable —
prereleases never win default resolution, so consumers are unaffected — and Phase 20 already spent
`0.8.1-rc.3` and `0.8.1-rc.4` this way. The cost is real but bounded and precedented.

Declining is a legitimate outcome. This phase's own honesty rule (carried from Phases 18, 19 and
20) says an unrun rehearsal is recorded as unverified rather than presented as working — but it
also says re-reading the workflow is not evidence, so declining leaves ARTIFACT-06's criterion 7
open and leaves RESEARCH.md's Assumption A1 (the digest wire format) and A2 (the aarch64 binary
set) unsettled.

There is also a hard sequencing fact: `make release` refuses to run off `main` and
`verify-tag-source` fails a tag whose commit is not an ancestor of `main`. The rehearsal cannot
run until plans 21-01 … 21-05 are merged.
  </context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator workstation → `origin` (tag push) | A push that triggers a publishing pipeline with registry write access |
| release workflow → crates.io / ghcr.io | Credential-bearing publish to two public registries |
| downloaded release assets → operator workstation | Artifacts fetched from the internet and executed locally during verification |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-25 | Elevation of Privilege | the rehearsal tag triggering `publish-crates` | high | mitigate | Unchanged Phase 19 controls: the job runs only under the `crates-io` GitHub Environment whose deployment policy admits exclusively `v*.*.*` tags, minting a short-lived OIDC token per run with no long-lived secret; `verify-tag-source` additionally requires the tag commit be an ancestor of `main`, and the blocking checkpoint requires a human to authorise the version consumption |
| T-21-26 | Repudiation | a rehearsal reported as run when it was not | high | mitigate | The evidence file has exactly two permitted shapes — measured with run URLs, or explicitly unverified with reasons — and the acceptance criteria assert one of them is present; there is no state in which silence reads as a pass |
| T-21-27 | Tampering | executing downloaded binaries during verification | medium | mitigate | The binaries are verified against the aggregated checksum file before execution and are the run's own build output; `--version` is a read-only invocation, and no downloaded artifact is executed with elevated privileges |
| T-21-28 | Denial of Service | a failed rehearsal leg tempting a re-tag | medium | mitigate | The action forbids re-tagging with a fresh version on failure and directs the operator to fix forward and use the workflow's own re-run, which every job is safe to serve (Phase 20 D-03) — this bounds prerelease-version consumption to one per rehearsal |
| T-21-29 | Information Disclosure | run logs and evidence capturing token material | medium | mitigate | Only job outcomes, digests, sizes, asset names and command outputs are transcribed; no step echoes `GITHUB_TOKEN` or the minted crates.io token, and the evidence file is reviewed for credential text before commit |
| T-21-SC | Tampering | package installs | low | accept | RESEARCH.md's Package Legitimacy Audit records **no new packages and no new Actions**; `cargo-release` is a pre-existing, already-required local tool the `make release` target checks for rather than installs |
</threat_model>
